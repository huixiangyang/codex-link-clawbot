# 安全模型

项目面向单个可信使用者，不是多租户服务。微信绑定和管理令牌能够驱动本机已有的工作流程，应按宿主操作权限保护，而不只当成聊天入口。

## Codex 的宿主权限

当前 [线程启动](../../internal/adapters/appserver/threads.go)与[轮次提交](../../internal/adapters/appserver/turns.go)固定使用 `approvalPolicy=never` 和完整访问沙箱策略。任务可能读取文件、执行命令、访问网络或修改项目，不会逐项征求批准。

工作空间白名单只决定允许选择哪些会话和工作目录，不构成 OS 文件隔离。管理 API 没有任意 Shell 端点，不意味着通过 Codex 的工作没有 Shell 能力。附件草稿、确认页和令牌认证都不能替代操作系统隔离。

部署应使用专用普通账号，只保留必要文件与环境凭据，不把个人全部目录交给服务账号。只绑定可信微信，避免在状态根或工作目录中放置无关秘密。

## 远程身份与本机身份

微信只接受启用绑定者的完成态私聊消息。多个凭据必须明确选择一个绑定，切换需要停服。管理台访问请求和结果时使用相同所有者范围，客户端不能传入另一个 owner 绕过隔离。

本机 CLI 依赖操作系统身份和私有目录权限，不使用网页令牌。能读取服务账号状态数据库的人，也能读取微信凭据和管理令牌，因此必须保护该账号及备份。

## 网页管理令牌

首次初始化生成 32 字节随机值，以 64 位十六进制保存在 SQLite 的 `settings` 中。`console` 显式打印入口与令牌，管理台通过 `X-Codex-Link-Token` 发送，服务端常量时间比较。

令牌不进入页面 HTML、管理 URL 或诊断日志；浏览器只存于当前标签页 `sessionStorage`。没有默认密码，远程解锁码也不是管理令牌。令牌错误时，应在实际运行账号和主机执行 `console`，确认 URL 对应同一实例后重新连接，不要在聊天中索取或发送令牌。

## 网络与浏览器

管理 TCP 只能监听回环地址，默认 `127.0.0.1:18120`。外部访问由 HTTPS 反向代理或 Tunnel 转发，`management.public_url` 只展示地址，不创建隧道、不改变监听或认证。

响应设置同源 CSP、禁止 frame、`no-referrer`、`nosniff` 和受限 Permissions Policy；API 不启用跨域响应头，不使用第三方脚本或字体。反向代理必须保留管理令牌请求头，不能把令牌塞进 URL，也不能用边缘认证替代应用认证。

本机 `control.sock` 提供生命周期接口，与网页 API 分离，不能通过代理公开。远程锁只控制微信工作入口；持有网页管理令牌者仍可操作管理台，它不是第二层网页登录认证。

## 数据和下载

状态目录权限为 `0700`，数据库、WAL/SHM、附件和日志为 `0600`；受管状态路径拒绝符号链接。数据库包含配置密钥、令牌和消息内容，不能作为静态资源提供下载。

下载必须经过所有者、期限和登记清单校验，只允许请求已归档的文件。打开路径受目录句柄约束，目标文件校验身份、类型、大小和 SHA-256，并从同一已校验句柄返回。修改任意路径参数不能下载工作目录或数据库。

执行日志有脱敏，但上游错误可能包含无法识别的敏感文本，分享前仍需人工检查。业务备份与数据库具有同等敏感性；保留、清理与回滚边界见[数据与产物](../design/sqlite-storage.md)、[日志](../operations/logging.md)和[部署](../operations/deployment.md)。
