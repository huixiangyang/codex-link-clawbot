# 持久交互与控制回执

## 1. 实现结果

数字菜单和待输入操作不再保存于 `Handler.sync.Map`。运行时启动时强制打开严格 v14 `~/.codex-link-clawbot/control-state.json`；初始化失败会阻止服务启动。每次菜单变化都通过统一 `statefile` 内核原子提交。

服务重启不会使仍在有效期内的数字菜单、线程名称输入、改名输入或线程搜索失效。用户继续回复时，控制层读取当前 owner 的 revision，并只消费这一版状态。

## 2. 磁盘边界

每个 owner 最多有一项当前交互，持久字段只有：

- 128 位随机 revision。
- 稳定 view ID、交互模式和到期时间。
- 显式稳定编号、有序的类型化 action、目标 ID、页码、归档标记、受限筛选词和翻页方向。
- 返回动作。

卡片正文、选项标签、Codex 提示词、回答、附件名、文件路径、URL、账号令牌和 `context_token` 不进入菜单状态。重启后的数字操作按显式编号查找持久 action，不依赖数组位置；重复编号和越界编号都会拒绝，不把旧卡片正文复制进状态文件。

文件上限 256 KiB，最多保存 64 个 owner、每个菜单 48 个动作。文件和目录继续由状态内核强制使用 `0600`、`0700`，未知字段、未知动作、重复编号、非法 view、超限文本、错误 revision、符号链接和尾随 JSON 全部拒绝。

## 3. revision 与过期

每次打开下一张菜单或输入态都会生成新 revision。数字回复通过原子 compare-and-delete 消费当前 revision；并发或迟到回复只能有一个成功。普通文本会退出旧选择态后进入自然语言控制或 Codex。

全局工作台包含实时线程状态，`1`–`9` 与 `11`–`43` 数字绑定有效期为 5 分钟；直接斜杠命令不依赖 revision；其他对象列表、确认和待输入交互仍为十分钟。过期数字、返回和翻页短语会明确提示“操作已经过期”，绝不进入 Codex；过期普通文本仍按普通消息处理。

## 4. 控制动作回执

所有修改状态或产生外部交付的意图必须声明 `RequiresReceipt`。自然语言动作执行前保存微信稳定来源键；数字动作把“消费菜单 revision”和“保存来源回执”放在同一文件事务中。

回执只保存：经过账号哈希隔离的来源键、owner 哈希、稳定 action ID、领域、创建时间和过期时间。它不保存结果正文、目标内容或投递参数。回执保留 24 小时并受固定容量限制。

同一来源键再次到达时直接返回“已经处理”，不会再次创建线程、切换状态、取消 codex-link-clawbot 当前执行、重试、再次发送媒体或生成语音。相同来源键若指向不同动作则按冲突拒绝。

控制回执采用保守的 at-most-once 语义：回执必须先于领域副作用提交。进程若在回执提交后、动作完成前终止，重启后不会猜测或自动重做，用户需要用新消息重新确认。这一选择避免线程、删除、锁定、媒体和语音出现不可控重复；持久请求入队本身仍使用来源键提供额外去重。

任务重试、成功请求再次执行和审查后的“继续修复”是仅有的可安全自动重投例外：若队列持久化或入队确认失败，控制层会在同一状态文件中删除本次回执并恢复原菜单 revision，让微信重投再次进入相同动作。即使第一次其实已经入队，请求来源键也只会返回已有请求，不创建第二项。

## 5. 破坏性边界

- 删除内存菜单作为事实来源，不双写、不回读旧进程状态。
- v14 在目标线程管理页破坏性加入一层关系图入口，并为关系节点增加十分钟持久编号；v1–v13 菜单与回执全部清空。首页仍保持 v13 建立的五分钟全功能工作台、15 个稳定直达和 17 个微信可执行命令。Codex 历史、焦点索引、codex-link-clawbot 请求队列、偏好、交付和审查原生线程记录不受影响。
- 修改状态的控制消息没有稳定 `message_id` 或 `seq` 时直接拒绝执行。
- 旧“过期数字进入 Codex”行为删除，统一改为明确过期结果。
- 菜单存储失败时返回稳定的“操作状态暂不可用”，不展示底层路径或错误文案。

## 6. 自动化验证

自动化测试覆盖：

- 重建 `Handler` 和重新打开状态文件后继续数字菜单。
- 首页动态线程编号、`5`–`9` 高频动作与 `11`–`43` 稳定直达跨同版本重启保持；重复编号和未知 schema 被拒绝。
- 重启后继续待输入的线程创建。
- revision 匹配与不匹配消费、严格过期和磁盘删除。
- 显示正文与标签不落盘，动作参数完整恢复。
- 回执跨重启去重、来源冲突和菜单消费与回执原子提交。
- 注册表解析 49 个官方主命令与 5 个别名；首页和可用命令目录只投影其中 17 个 codex-link-clawbot 可真实执行的命令，修改型斜杠命令同样先提交最小控制回执。
- 重试或成功请求复用入队失败时回执回滚、原 revision 恢复。
- 重复线程创建和重复请求复用不会执行第二次。
- 缺少稳定来源键时修改动作不会进入领域控制器。
