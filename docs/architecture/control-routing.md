# 类型化控制路由

## 1. 已完成边界

微信控制消息现在固定经过以下单向链路：

```text
规范化文本
  → Intent Registry
  → 唯一领域控制器
  → ActionResult
  → Delivery Presenter
  → 微信或 codex-link-clawbot 持久请求队列
```

自然语言不再依赖按顺序尝试的条件链。数字菜单也不再进入跨工作空间、线程、请求队列、偏好、交付和安全领域的大 `switch`。两类输入最终都进入相同的领域控制器边界。

后续 C 批次已完成：[持久交互与控制回执](persistent-interactions.md) 删除了内存菜单，并将类型化 action 直接写入 revision 状态，没有建立双写或兼容层。

## 2. Intent Registry

注册表与领域枚举位于 `internal/control`，微信协议层不能私自扩展另一套意图表。消息运行时由 `internal/app` 一次性注入默认注册表，启动后不可替换。

每项意图必须声明稳定 ID、领域、规范化短语、可选参数前缀、安全属性和审计事件。默认注册表覆盖系统、codex-link-clawbot 队列、工作空间、Codex 线程、偏好、交付和安全七个领域。请求队列标识使用 `queue.*`，Codex 线程使用 `thread.*`，真正的 Codex 轮次操作才使用 `turn.*`。旧 `task.*`、`session.*` 和误用为队列的 `turn.*` 不再写入。

注册阶段执行确定性冲突检查：

- 重复 ID 拒绝启动。
- 大小写和末尾常用标点规范化后，相同短语拒绝启动。
- 一个领域的精确短语被另一领域的参数前缀捕获时拒绝启动。
- 不同意图的参数前缀互相包含时拒绝启动。
- 普通文字没有唯一匹配时原样进入 Codex，不能被控制层静默吞掉。

带图片或文件的消息默认不能触发控制动作。只有意图显式声明 `AllowAttachments` 才能越过这一边界；当前默认注册表没有开放此权限。

## 3. ActionResult

控制器只能返回 `ActionResult`：

- `ActionID`：稳定动作标识，不能为空。
- `Domain`：固定领域枚举，未知值直接拒绝。
- `Text`：面向绑定者的结果或下一步说明。
- `Effect`：最多一项类型化进程内副作用。

允许的副作用只有：codex-link-clawbot 请求入队、创建重试请求、取回冻结文字、发送已归档媒体、生成语音简报。副作用参数不进入卡片、日志或持久菜单。纯文字结果必须包含正文；媒体结果必须同时包含受控路径和发送回执；未知或不完整结果在触达微信前失败。

旧的 `controlDispatches`、`controlRetries`、`controlFrozenTexts`、`controlMedia` 和 `controlVoice` 已删除。控制器不再先写共享 map，再要求外层猜测应该执行什么。

## 4. 领域控制器

自然语言分发和数字动作各自只做一次领域选择，随后进入对应控制器：

- 系统：操作总览、帮助、运行信息。
- codex-link-clawbot 队列：执行状态、取消、请求列表、重试和冻结文字。
- Codex 工作空间：受信任目录信息与默认执行目录切换。
- Codex 全局与线程：跨客户端浏览、搜索与接管；目标线程的新建、改名、分叉、置顶、压缩、目标、模型、审查、归档、恢复、删除、官方斜杠命令解析和当前轮次追加指令。
- 偏好：回答方式和视觉风格。
- 交付：交付箱、交付详情和再次发送。
- 语音简报属于最近成功结果的按需交付，不形成独立领域或设置入口。
- 安全：远程锁定。

Codex 轮次执行期间的修改限制由意图元数据统一判断。线程浏览和归档列表可以读取；追加指令可以进入当前 Codex 轮次，其他线程修改由运行时独占边界阻止。

## 5. Presenter 与失败语义

Presenter 是控制动作唯一的微信副作用出口。它先校验结果，再选择文字卡片、持久入队、重试、冻结文字、媒体或配对语音交付。

持久入队和重试具有来源键，失败可以交给微信同步重投。其他动作可能已经修改状态，发送回执失败只记录脱敏错误，不能重新执行动作。语音成功时阅读卡和 MP3 已形成完整交付，不追加低信息量状态卡。

## 6. 自动化验证

```bash
go test ./...
go test -race ./internal/statefile ./internal/request ./internal/bridge ./internal/ilink ./internal/management ./internal/cli
go vet ./...
```

测试覆盖意图唯一性、大小写与标点规范化、普通 Codex 文本不误捕获、附件权限、运行中轮次修改边界、类型化副作用、非法结果投递前拒绝，以及工作空间、线程、轮次、视觉和语音流程。
