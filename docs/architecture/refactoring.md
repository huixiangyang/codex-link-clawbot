# 架构分析与调整记录

## 项目判断

这是一个 Go 单进程应用：微信长轮询负责输入，执行记录与拒绝回执负责追踪和去重，Codex App Server 负责执行，嵌入式 Web 页面与本机 Unix socket 提供管理入口。现有工作空间、线程、请求、交付物和状态文件已经分包，主要维护成本来自应用编排与传输适配之间的耦合。

本轮继续采用模块化单体。会话执行权、本机文件状态与单个 Codex 子进程本就属于同一运行实例，拆成远程服务会增加部署与一致性成本。

## 已完成的调整

| 原问题 | 调整 | 开发收益 |
| --- | --- | --- |
| 微信协调器直接读取 Handler 的 Codex、线程、锁定、进度和通知字段 | 调度移到 `execution.Coordinator`；`bridge.taskExecutor` 实现 `Executor` 接口，通过明确的回调发送结果 | 可在没有微信或 Codex 的情况下验证取消、排空和互斥；调度不受消息协议改动影响 |
| 排空检查与领取任务分离；启动排空发生在协调器注入之前 | 准入与排空共用临界区；装配完成后应用初始排空状态 | 消除排空窗口，`start --draining` 在第一次准入前生效 |
| app 只等待部分后台循环，启动中途失败没有统一取消和回收 | 引入仅供组合根使用的 `serviceGroup`；HTTP 关闭逻辑统一 | 启动失败和运行故障沿同一退出路径，便于定位原始错误和热重启 |
| StateRoot 只用于管理令牌与 socket，领域存储隐式读取默认目录 | 组合根显式传递领域存储路径 | 应用装配的状态目录可预测，避免不同入口各自决定持久化位置 |
| 本地 Makefile 与 CI 重复维护检查清单 | CI 直接运行 `make check`，增加快速检查与按包测试 | 开发与提交使用相同验收入口 |
| Air 传入不存在的 `-f`，未监听嵌入的 JS/CSS，直接强杀进程 | 修正启动参数、监听静态资源、先发送中断并留出退出时间 | 前后端改动均触发重建，编译失败停止旧实例 |
| macOS 默认临时目录触发拒绝符号链接规则，真实路径又可能超过 socket 长度限制 | Makefile 使用 `/tmp` 对应的真实短路径 | 保留生产路径安全校验，在 macOS 与 Linux 上复用测试 |

旧协调器已删除，没有转发包装或兼容别名。第一阶段保持协议不变；之后的业务重整已升级请求索引为 v4、输入与结果清单为 v2，并替换管理 API，见[业务设计](../../specs/business-reset/design.md)。

## 依赖方向

```text
cli → app → bridge / management / codex.appserver
               │          │
               └── execution → request

bridge.taskExecutor → codex / thread / workspace / delivery
领域存储 → statefile
```

协调器只决定谁可以执行、是否准入、何时可以取消。执行适配器负责打开线程、提交轮次、冻结结果和记录交付。微信 Handler 负责入口校验、执行接收回执与回复呈现，只持有会话控制接口，不负责轮次执行。

## 后续模块边界

以下是独立的后续改进方向，本轮未扩大到这些模块：

- `codex/appserver/client.go` 仍集中承担子进程、RPC、事件解码和线程操作；协议扩展时可按 transport、events、threads 拆分，并保持唯一客户端入口。
- 管理端已按请求、会话与基础配置拆分 HTTP 文件；增加第二种管理入口时，再抽出共享用例服务。
- 回复渲染仍由 Handler 实现，执行器通过单一发送回调使用它；新增消息渠道时再独立呈现组件，避免提前引入渠道框架。

## 验证边界

复用现有请求冻结、确认顺序、图片文件交付和状态恢复测试。新增回归只覆盖调度取消与收尾竞争、排空/恢复、运行时互斥、服务失败回收及 HTTP 在途请求退出。依赖方向继续通过已有架构测试校验。

`make check` 验证代码、文档与 race 测试；实际微信账号、真实 Codex 子进程和 Air 热重载仍需按[验收清单](../operations/acceptance.md)联调，不能用本地测试替代。

## 手机数字菜单

微信新增独立的单键菜单适配器，使用现有目标、线程、请求、偏好与恢复服务。每页只映射可见选项的完整 ID，执行仍由唯一协调器负责。菜单会话十分钟有效，收件去重记录独立持久化，图片呈现与业务状态分离；不恢复旧控制意图解析器。详情见[数字菜单设计](../design/wechat-menu.md)。
