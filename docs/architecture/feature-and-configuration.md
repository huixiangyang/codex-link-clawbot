# 功能与配置模型

## 全局远程工作台

codex-link-clawbot 的首页围绕整台机器上的 Codex 工作组织，而不是围绕当前微信会话组织：

```text
Codex 全局工作台
  ├─ 当前目标：下一条微信输入的唯一落点
  ├─ 最近线程：标题、工作空间、Codex 状态、活动时间和微信执行标记
  ├─ 高频动作：全部线程、新建、执行与队列、工作空间、刷新
  └─ Codex 功能：17 个微信可用斜杠命令按三组直接展开

Codex 全局总览（11）
  └─ 全局事实：工作空间、全部线程、运行中线程、微信队列
```

`/` 返回单张 1080×780 固定艺术画布。最近线程和五个高频动作严格收在左上；右上以单行遥测带显示工作空间、全部线程、运行中和微信队列四项真实事实，线程拓扑从遥测带下方展开；三者共同压缩在顶部 390 像素信息带中。其余区域直接展开 17 个 codex-link-clawbot 可真实执行的 Codex 斜杠命令。图片不再渲染独立统计卡、当前目标面板、页面级标题或表格边框：最近线程以纯单列显示标题、工作空间、活动时间、状态和当前标记，五个高频动作收为列表下方的微型命令带，三个命令列面板同时显示中文和规范 `/command`。最近线程使用动态编号 `1`–`4`，固定高频动作使用 `5`–`9`；`11`–`43` 的 15 个稳定直达动作也写入同一版首页状态，无需进入二级目录：

| 范围 | 编号 | 责任 |
| --- | --- | --- |
| Codex 全局 | `11`–`13` | 全局总览、全局线程、账号与额度 |
| Codex 工作空间 | `21`–`25` | 工作目录白名单、目标线程、模型权限、技能工具、微信可用命令 |
| Codex 执行 | `31`–`34` | 新建、审查、请求队列、取消 |
| codex-link-clawbot 远程 | `41`–`43` | 结果交付、健康诊断、呈现安全 |

Codex 项采用“中文 · `/command`”双标识。官方 49 个主命令和 5 个别名继续由注册表识别，但首页、可用命令目录和文字降级菜单只展示其中 17 个稳定 App Server 原生或微信适配能力。终端 UI、Windows 和实验协议专属项不进入任何微信菜单。用户直接发送可用 `/command`，不经过分类或分页；未知命令不进入提示词。

## 上下文归属

- 成功纯文字请求可以在 24 小时内继续原线程、再次执行或在新线程执行；codex-link-clawbot 不维护独立提示词模板或收藏库。
- 文件属于执行结果。`41` 汇总最近成功结果、带工作空间/线程/请求来源的严格 v3 交付箱，以及对最近结果的按需语音播报；再次发送前必须通过 SHA-256 校验。
- 工作空间只限定 Codex 可见、可接管和可执行的受信任目录，不承载服务、健康地址或定时任务。
- `42` 是诊断唯一入口，有效配置不在设置中心重复出现。
- `43` 只管理个人回复方式、视觉风格与远程锁定；语音播报不在这里重复出现。

纯链接作为普通内容交给 Codex。codex-link-clawbot 不提供通用主动发送 TCP API；受限部署完成事件和长任务恢复提醒进入待阅状态，只在绑定者下一次有效交互时合并补送。

## 三种状态范围

- 全局事实：Codex `thread/list`、`account/read`、`model/list`、`skills/list`、`mcpServerStatus/list`。
- 远程焦点：默认工作空间与目标线程，仅决定下一次上下文操作落点。
- codex-link-clawbot 执行：微信请求从落盘、排队、Codex 轮次到微信交付的可靠状态。

当前目标、Codex 运行中和 codex-link-clawbot 执行中必须分别呈现。一个空闲线程可以是当前目标；多个非目标线程也可以由桌面端或 CLI 同时运行。只有“当前目标”决定下一条普通微信内容进入哪里。

执行中的请求只展示与本次 `turnId` 对应的结构化轮次阶段。阶段来自 App Server 的轮次、工作项和计划通知；说明消息、命令输出、终端交互和差异不构成阶段。重复签名合并，终态冻结进度；该状态属于 codex-link-clawbot 请求，不写入 Codex 线程。

本地线程索引不得作为全局可见性来源。全局线程必须按真实 `cwd` 落入受信任工作空间；桌面端、CLI 和 IDE 创建的线程均可见。目标线程的修改命令仍只作用于目标，不扩散到其他线程。

线程关系图同样不使用本地索引推导拓扑。它只以当前目标的 `forkedFromId` 和本次全局目录中指向当前目标的直接子节点现算一层关系，最多呈现五个子节点并明确截断数量。图中编号只保存受限线程 ID 与工作空间 ID，接管时必须重新读取线程并复核真实路径。

## 配置边界

配置文件顶层固定为：

```text
schema_version
codex
codex-link-clawbot
  ├─ project_entries   # 只含 id、name、root
  ├─ reply
  └─ security
```

机器配置只能由本机文件、受控环境变量和部署事务修改。微信端可以选择默认工作空间、目标线程、回答方式和视觉风格，但不能添加目录、修改 Codex 命令、凭据、审批策略、沙箱或 TTS 密钥。

`codex-link-clawbot config` 输出脱敏有效配置；微信状态只展示启用状态和数量，不显示绝对路径、URL、账号原文、凭据或环境变量值。账号邮箱在微信中掩码展示，退出登录和凭据修改不开放。

## 破坏性迁移

配置结构严格使用 `schema_version: 6`。旧品牌键、无版本、v2–v5、扁平配置和已下线的 `message_interval_seconds` 全部拒绝，不自动转换。短期菜单状态使用严格 v14，当前命名空间中的 v1–v13 菜单与控制回执直接置空。

`automation-state.json`、`project-watch-state.json`、`scheduled-reports-state.json` 和项目关注待阅通知被销毁，不迁入其他状态。交付库 v1/v2 及其无法补齐来源与摘要的旧私有副本同样销毁，并重建为空 v3。Codex 历史、请求队列、工作空间选择、偏好、部署通知和长任务恢复通知保留。运行时不翻译旧字段、旧动作或旧 view。

## 验收不变量

- 首页会话数据必须限制在顶部信息带左侧，通过最多四个最近线程中的柔和选中态与“当前”标记表达目标；`5`–`9` 只能作为列表下方的一条微型命令带出现，不得伪装成会话行。右侧只能使用真实线程编号和状态生成抽象拓扑；顶部信息带固定为 390 像素。命令区必须占据其余画布，以三个等宽列面板完整显示 17 个微信可用命令，不得渲染 CLI、TUI、Windows 或实验协议专属项。
- `thread/list` 全局查询不得固定 `sourceKinds`，且必须在展示和接管时两次执行工作空间边界校验。
- 首页 `1`–`4` 必须冻结线程与工作空间绑定，`5` 是全局 `/resume`，`6` 是 `/new`，`7` 是执行队列，`8` 是工作空间，`9` 是刷新。
- `11`–`43` 的 15 个稳定动作必须从首页直接执行；`11` 是全局总览，`12` 是全局 `/resume`，`13` 是账号与额度，`22` 是目标线程 `/status`。
- `41` 只组织结果与交付，`42` 只组织健康诊断，`43` 只组织呈现与安全。
- `/resume` 不受本地焦点索引限制；`/status`、线程生命周期和设置仍只作用于目标线程。
- 关系图只能读取一层父子关系，不得读取正文或缓存线程树；图中节点接管必须再次通过工作空间边界校验。
- 工作空间页不得出现服务、健康、监控、提示词模板或收藏入口。
- 五套视觉风格必须完整渲染全局工作台的 17 个微信可用命令，不能混入只可在本机客户端使用的能力。
