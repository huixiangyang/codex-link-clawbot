# 功能与配置模型

## 目标

WeClaw 不再把所有能力当作同一层命令，也不再把机器配置和微信偏好混在一份扁平概念中。管理模型固定为四层：

```text
微信首页
  ├─ Codex 工作台：线程、模型、推理、目标、审查、技能与外部工具
  ├─ WeClaw 功能中心：提示词模板、素材、交付、自动化、语音简报
  ├─ WeClaw 设置中心：项目入口、回答方式、视觉风格、队列与远程锁定
  └─ WeClaw 诊断中心：运行状态、有效配置、无回复诊断和使用说明
```

WeClaw 请求单独占首页一块高频区域，回复呈现也保留直接入口；它们属于 WeClaw，不冒充 Codex 轮次或模型能力。

## 首页原则

`/` 继续返回单张 1080×2280 大图，避免用户通过多轮对话寻找入口，但首页只保留 35 个稳定动作：六个领域入口加 29 个高频直达项。低频的归档、恢复、分叉、压缩、详情、分页和二次确认进入相应领域中心。

编号归属固定：

| 编号 | 领域 | 责任 |
| --- | --- | --- |
| `1x` | Codex 工作台 | Codex 原生线程与执行能力 |
| `2x` | WeClaw 请求 | 入队、执行、记录、取消和暂停 |
| `3x` | WeClaw 回复 | 回答方式、视觉风格和语音简报 |
| `4x` | WeClaw 功能 | 模板、素材、交付与自动化 |
| `5x` | WeClaw 设置 | 有效配置、项目入口、回复、队列和安全 |
| `6x` | WeClaw 诊断 | 无回复诊断、运行状态、说明和刷新 |

动态状态只改变标签后的元信息，不改变编号和动作。首页 revision 保存 30 分钟，部署到新菜单版本时旧短期菜单与控制回执整体清空，不做动作映射兼容。

## 能力归属

“WeClaw 项目入口”和“Codex 能力”是两个独立页面：

- 项目入口只展示白名单目录、当前选择和确定性检查边界。
- Codex 能力只展示 Codex App Server 返回的技能、外部工具连接、模型与线程入口。
- 项目入口页不得出现技能、模型、审查或 Codex 线程操作。
- Codex 能力页可以显示当前工作入口名称，但不能把入口描述成 Codex 项目对象。

## 配置边界

配置文件顶层固定为：

```text
schema_version
codex
weclaw
  ├─ project_entries
  ├─ reply
  ├─ features
  ├─ security
  └─ send_api
```

机器级配置只能由本机文件、受控环境变量和部署事务修改。微信设置中心只写入绑定者自己的项目入口选择、线程选择、回答方式和视觉风格。这样微信凭据即使被误操作，也不能改写 Codex 命令、文件路径、TTS 密钥、服务名或网络暴露面。

`weclaw config` 输出有效配置的脱敏摘要，不输出 API 密钥、远程锁码、token 哈希或 Codex 环境变量值。微信“有效配置状态”只展示启用状态和数量，不展示命令、绝对路径、URL、账号或凭据。

## 破坏性迁移

配置结构版本为 2。部署候选在持有离线迁移锁时完成以下单向操作：

1. 先提取旧项目中的提示词模板。
2. 将旧扁平配置原子重组为 `codex / weclaw`。
3. 将控制状态升级为版本 5，并清空旧菜单与控制回执。
4. 新运行时只接受新结构。

迁移与服务切换处于同一部署快照事务中；失败恢复旧二进制与旧状态。代码中没有旧字段读取、双写或旧编号翻译。

## 验收不变量

- 首页始终是六个明确归属的领域与 35 个稳定动作。
- `11` 是当前 Codex 线程，`12` 是新建线程，`18` 是 Codex 能力。
- `41` 是提示词模板，`51` 是有效配置，`55` 是远程锁定，`61` 是无回复诊断。
- 项目入口页与 Codex 能力页不得混合责任。
- 微信配置状态与 `weclaw config` 必须反映同一份有效配置，且不泄露秘密。
- 旧扁平配置不能直接启动；旧菜单版本不能继续执行。
- 五套视觉模板必须真实渲染完整首页，不能因数据上限不一致降级文字。
