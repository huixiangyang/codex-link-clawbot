# 微信端与部署验收清单

当前生产从 v2.5 一次性切换到当前主线时，执行顺序、停止条件、备份、回滚和稳定观察以 [首次生产切换与真机验收](production-cutover.md) 为准；本文保留各领域的完整长期回归矩阵。

## 1. 项目、线程与操作总览

1. 空闲时发送 `/`，应只收到一张 1080×2280 操作总览图片，包含六个明确标注 Codex 或 WeClaw 的领域、六项状态和 44 个稳定编号；不得再补发重复说明文字。
2. 执行、发送、等待或暂停时再次发送 `/`，目录结构与编号必须不变，只有 WeClaw 执行、请求队列、最近结果、提示词模板和当前偏好的标签可以变化。
3. 依次验证 `1` Codex 线程，以及 `11` 新建、`12` 当前详情、`13` 切换、`14` 搜索、`15` 分叉、`16` 压缩、`17` 目标、`18` 归档和 `19` 恢复；分页返回保留页码与搜索词。
4. 验证置顶、永久删除及其二次确认；永久删除父线程时 Codex 与本地索引中的所有派生线程同时消失。
5. 切换 WeClaw 项目入口后，线程列表不得出现其他项目线程；已入队请求仍使用创建时固定的项目入口和线程。
6. 验证 `21` WeClaw 项目入口、`22` Codex 模型、`23` 推理强度、`24` 代码审查和 `25` Codex 能力；模型设置只影响当前线程的后续轮次，分叉后保持一致。
7. 任意旧工作目录切换或斜杠命令不得执行；配置中的 `codex.cwd` 必须导致启动失败。

## 2. WeClaw 持久请求队列

1. 启动一个长 Codex 轮次，连续发送两条文字、一张图片和一个 PDF；四项都应先成为 WeClaw 请求，在确认前落盘、只入队一次并按全局先进先出顺序执行。
2. 忙碌期间切换项目入口、线程、回答方式和视觉风格；旧请求使用入队快照，新请求使用新选择。
3. Codex 轮次执行期间发送“追加指令 先修复失败测试”，内容必须追加到同一轮次，不能创建新轮次；没有活动轮次时必须明确拒绝。
4. “请求队列”每页显示 6 条执行记录，按状态提供移到最前、删除、暂停、继续、取消、重试或取回冻结文字；清空队列必须二次确认且只影响当前绑定者的等待请求。
5. 暂停一个绑定者不应阻塞其他绑定者；远程锁定会取消 WeClaw 当前执行并暂停该绑定者，解锁后不得自动恢复。
6. 重复投递相同 `message_id` 或 `seq` 不得创建第二项，也不得再次下载附件。
7. 分别在 `queued`、`running`、`delivering` 阶段终止进程：等待请求继续排队，执行中和发送中请求转为人工处理中断，不得自动重复 Codex 轮次或整批消息。
8. 详情不得展示完整问题、回答、附件名、原始账号 ID、消息上下文令牌、终端输出或私有路径。

## 3. 投递事务

1. 明确拒绝发送时轮次进入 `failed/delivery_failed`；响应丢失或部分媒体可能可见时进入 `interrupted/delivery_ambiguous`，两者恢复说明必须不同。
2. Codex 完成后必须先冻结正文、图片 URL、视觉风格、回答方式和交付物哈希，再进入 `delivering`。
3. 成功或取消后立即清理请求和结果；失败或中断负载最多保留 24 小时。
4. 语音模式必须先完整预上传阅读卡和 MP3，再依次发送；超长回答先发完整阅读卡，再发明确标注的语音节选卡与 MP3。
5. TTS、渲染或预上传在可见发送前失败时降级为完整阅读卡，再失败则发送全文；发送结果不确定时不得盲目补发。
6. 回答方式和视觉风格重启后保持；`preferences.json` 的未知字段、非法枚举、旧版本和尾随数据必须拒绝启动。
7. 普通阅读模式的多张回复也必须整批预上传后再发送；第二张预上传失败时第一张不得可见并应降级全文，第一张已可见后第二张发送响应不确定时不得补发全文。

## 4. 图片、素材、交付与自动化

1. 图片和文件在排队时写入 `~/.weclaw/tasks/<task>/inbox`；Codex 执行时图片以 `localImage` 输入，文件只作为不可信附件引用。
2. 要求 Codex 生成文件，微信收到后“交付记录”应出现私有副本；轮次临时目录清理后仍能再次发送。
3. 图片批注必须生成新 PNG，不覆盖原图；长回复按所选刊物、构筑、黑标、可爱或简洁风格生成阅读卡，“文字版”可取回全文。
4. 自动化详情必须直接读取受限 Git/systemd/HTTP 检查，不调用 Codex 或自由 Shell；相同指纹不得重复通知。
5. 无标题短回复不得虚构大标题；单页不得显示页码或进度条，多页只在第一页显示大标题、只在最后一页显示“文字版”入口，发送后不得追加重复说明文字。
6. 任务清单、2–4 列 Markdown 表格、超长表格单元格和代码块必须保持结构且无截断；阅读图高度应随内容在 720–2200 像素间收敛，典型混合回复不能把一个短代码块单独挤到尾页。

## 5. 类型化控制路由

1. 默认自然语言短语必须由 Intent Registry 唯一解析；重复 ID、规范化后重复短语、跨意图前缀覆盖和重叠前缀必须在注册时失败。
2. 普通 Codex 文字不得被控制层捕获；图片或文件消息只有在意图显式允许附件时才能触发控制动作。
3. 自然语言和数字菜单必须进入同一组领域控制器；跨领域大路由以及 `controlDispatches`、`controlRetries`、`controlFrozenTexts`、`controlMedia`、`controlVoice` 必须不存在。
4. 每项结果必须包含有效 action ID 和领域；空文字、缺少副作用参数、未知副作用和携带隐藏值的语音动作必须在发送微信前拒绝。
5. 提示词模板、重试、冻结文字、媒体和语音只能通过 Presenter 执行。非持久控制动作的回执发送失败不得导致状态动作被微信重投再次执行。

## 6. 持久交互与控制回执

1. 打开操作总览或任意数字菜单后重建 `Handler` 并重新加载状态文件，原编号仍能执行；新 view 必须生成不同 revision。
2. 线程新建、改名和搜索的待输入状态在重启后继续；过期数字、返回和翻页必须明确拒绝且不得进入 Codex。
3. 严格 v4 `control-state.json` 只允许保存 revision、view、模式、过期时间、显式编号和受限 action 参数；卡片正文、标签、提示词、回答、路径、附件名、令牌和 `context_token` 不得出现。重复编号、v1/v2/v3 运行时读取和未知版本必须拒绝。
4. 同一 revision 的并发回复最多一个成功；有副作用数字动作必须把 revision 消费和来源回执放在同一个原子文件事务。
5. 重复来源键不得再次创建线程、切换状态、删除、取消、运行提示词模板、重试、发送媒体或生成语音；同一来源键映射到不同动作必须拒绝。
6. 修改状态的消息缺少稳定 `message_id` 与 `seq` 时必须失败关闭。回执只保留最小哈希身份和 action 元数据，24 小时后过期。
7. 提示词模板和请求重试若在持久入队或确认阶段失败，必须删除控制回执并恢复原 revision；重投仍由请求来源键保证最多一个队列项。

## 7. 统一状态内核

1. 偏好、项目入口、远程锁、Codex 线程、自动化、素材库、微信游标、WeClaw 请求队列 JSON、配置和账号凭据不得再包含独立的 `CreateTemp + Rename` writer。
2. 分别在 write、文件 sync、rename 和目录 sync 注入失败，旧文件必须仍可严格读取；内存状态不得声称未提交的新值。
3. 文件和目录权限分别收紧为 `0600`、`0700`；目标、临时项或任一路径祖先为符号链接时必须拒绝，且不得穿过链接创建文件。
4. 未知字段、尾随数据、截断 JSON、错误版本和超限文件必须分别归入稳定的 `schema`、`corrupt` 或 `capacity` 分类。
5. 服务持有状态锁时离线迁移必须返回 `conflict`；服务停止并释放后，同一迁移必须可以执行且保持幂等。
6. 无版本账号凭据只允许由离线迁移转换为严格 v1；运行时不得兼容或双写旧格式，损坏凭据不得静默跳过。
7. 私有备份清单的路径、大小和 SHA-256 必须稳定；修改任一备份文件后校验必须失败。

## 8. 游标、健康与排空

1. 入队写盘失败时不得推进微信同步游标；恢复磁盘后同一消息可以成功入队。
2. 一批消息中前项成功、后项失败时，私有消费回执应避免重做前项，同时保留整批旧游标。
3. `weclaw status` 必须通过私有 Unix socket 返回严格结构化状态，包括版本、运行状态、Codex、微信监控、轮次数与排空状态；不得回退到 TCP 健康接口。
4. 排空期间仍可接收和持久化消息，但 Coordinator 不领取新任务。只有运行、发送、staging 和待提交同步批次都为零时 `drain_complete=true`。
5. 健康、排空、恢复和部署通知只存在于当前用户拥有的 `~/.weclaw/control.sock`；socket 必须为 `0600`，TCP `/health` 与 `/admin/*` 必须返回 404。

## 9. 确定性无回复诊断

1. 发送“为什么没回复”或从运行中心选择同名入口，必须由系统控制器直接处理，不得创建 Codex turn；远程锁定时该入口仍可使用。
2. 诊断按固定优先级识别远程锁定、排空或停止、Codex 未就绪、微信监控异常、两分钟无成功轮询、超过 30 秒的待提交批次、15 分钟内的持久化错误、队列暂停、执行或发送、等待以及 24 小时内的失败或中断。
3. 当前诊断消息自身所在的待提交批次不得被误报为阻塞；没有确定性依据时必须明确说明无法断言，不能编造网络、Codex 或微信原因。
4. 登录过期、服务端非零 `ret` 或非零 `errcode` 必须把微信监控标记为不健康，且不得刷新最近成功轮询时间。
5. 回复最多包含三条依据和三个建议，不得出现绑定者 ID、问题正文、回答、附件名、文件路径、URL、令牌、环境变量、原始错误或命令输出。

## 10. 主动发送 API 安全

1. 默认配置不得创建 TCP 监听；`api_addr`、`WECLAW_API_ADDR`、`start --api-addr` 和直接读取微信凭据的旧 CLI 发送路径必须不存在。
2. 未认证、错误 token、caller 不匹配、错误文字/媒体 scope、未绑定目标和非可信代理来源必须在任何发送与回执副作用前拒绝。
3. 相同 caller 与幂等键重投同一请求只发送一次；同键不同请求返回 HTTP 409。明确失败和可能已可见的失败也不得自动重发。
4. 请求超过 32 KiB、文字超过 8,000 字符、媒体不是公网 HTTPS 或下载超过 25 MiB 时必须拒绝；媒体下载不得访问回环、私网、链路本地或 DNS 重绑定地址。
5. `~/.weclaw/send-api-state.json` 必须为严格 v1、`0600` 且最多保留 24 小时；不得包含正文、目标绑定者、URL、原始幂等键、token、附件名或 `context_token`。
6. `weclaw send-token` 生成 256 位随机明文并只输出一次；可写入配置的 token 项只能包含小写 SHA-256 哈希和最小 scope。

## 11. 事务部署与回滚

1. `update`、`upgrade`、daemon、PID 文件和 `scripts/cutover-local.sh` 必须不存在。
2. 发布部署使用 `weclaw deploy <version>`；本地构建使用 `weclaw deploy --binary /absolute/path --expect-version <version>`，候选必须自证精确版本和 Linux 架构。
3. 发布物必须通过 `checksums.txt` 的 SHA-256；任何下载、校验或版本错误都不得排空或替换服务。
4. 旧服务排空并停止后才创建一致状态快照和运行离线迁移。新服务先以排空模式启动，健康验收前不得领取旧队列。
5. 目标版本就绪后，systemd 单元不得残留 `--foreground` 或 `--draining`；队列显式恢复并发送纯文字部署通知。
6. 注入迁移失败、启动失败或版本不符，必须恢复旧二进制、systemd 单元、配置、同步游标和完整任务状态，并验证旧版本重新 `ready`。
7. 部署收据不得含正文、令牌或附件名；成功后立即删除包含私密任务负载的状态快照。

## 12. 持久提示词模板

1. `projects[].quick_tasks` 必须由严格配置解码拒绝；运行时只能从 `~/.weclaw/workflows.json` 读取快捷工作流，不能保留配置回退或双写。
2. 离线迁移必须把旧提示词模板复制到每个已绑定者的对应项目，全部落盘后才删除配置字段；没有绑定者、定义冲突或工作流写入失败时保留原配置并失败。
3. 工作流按绑定者和项目双重隔离；另一个绑定者或切换后的项目不得读取、修改、删除或执行当前定义。
4. 名称、提示模板、参数槽、数量和总文件大小必须有固定上限；未知字段、未声明占位符、重复参数和配置外项目必须拒绝。
5. 参数渲染只替换声明的 `{{slot_key}}`，缺少、多余、空值、超限值或残留占位符不得进入 WeClaw 请求队列。
6. `workflows.json` 必须使用统一状态内核的 `0600`、严格 v1 和原子写入；更新或删除写盘失败后内存与旧文件保持不变。
7. 微信内必须能完成提示词模板分页、脱敏详情、创建、重命名、编辑和二次确认删除；空项目也必须保留创建入口。
8. `「参数名」` 必须按首次出现顺序编译为稳定内部槽；重复标签复用同一槽，未闭合、超过八项或用户输入内部双花括号必须拒绝。
9. 两参数模板必须逐项收集、重启续填并只入队一次；图片和文件不能成为参数，参数值和模板不得进入通用菜单状态。
10. 最终参数入队失败必须删除对应无正文回执并恢复到最后一项；重投后仍只生成一个轮次，且项目 ID 固定为模板所属项目。
11. 成功纯文字轮次只可保留严格 v1 `reusable.json`，其中只有原始请求；`context_token`、来源键、附件元数据、Codex 回答、交付物和终端输出不得出现。
12. 成功附件轮次必须删除整个私密负载；纯文字复用副本超过 24 小时、轮次记录被删除或终态记录淘汰后也必须删除。
13. 成功执行记录必须按能力展示继续原 Codex 线程、再次执行、在新线程执行和保存为提示词模板；缺失线程或复用副本时不得显示伪入口。
14. 原线程再次执行必须冻结轮次的项目和线程；新线程执行必须冻结项目并显式保持空线程，不能读取入队时的界面当前线程。
15. 自然语言重跑若入队失败必须删除控制回执；微信重投仍由轮次来源键保证只生成一个轮次。
16. 操作总览必须保持六个领域与 44 个稳定编号；最近结果、提示词模板数量、暂停/继续、当前风格和不可用原因只能改变标签。`57` 与 `32` 在执行时重新解析最近 WeClaw 执行记录，不能把临时队列编号固化到总览状态。

## 13. 自动化验证

```bash
go test ./...
go test -race ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./cmd/weclaw
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build ./cmd/weclaw
```

最终真机验收至少覆盖：WeClaw 请求队列分页、文字/图片/PDF 连续排队、暂停与继续、取消、重启恢复、语音配对交付、部署通知和一次故障回滚。所有卡片不得泄露账号、路径、令牌、原始 diff 或终端输出。
