# 微信端与部署验收清单

当前生产从 v2.5 一次性切换到当前主线时，执行顺序、停止条件、备份、回滚和稳定观察以 [首次生产切换与真机验收](production-cutover.md) 为准；本文保留各领域的完整长期回归矩阵。

## 1. 工作空间、线程与操作总览

1. 空闲时发送 `/`，应只收到一张 1080×780 的艺术画布。最近线程与 `5`–`9` 必须收在顶部左侧；右上单行遥测带必须按工作空间、全部线程、运行中、微信队列的顺序显示本版事实，线程拓扑位于其下方且只能使用本版线程编号与状态。顶部信息带固定为 390 像素；其余区域必须通过三个等宽列面板完整显示 17 个微信可用命令，不得出现页面级大标题、独立统计卡、当前目标面板、表格边框、虚构事实或客户端专属命令。
2. 当前目标、Codex 运行中和 codex-link-clawbot 等待/执行/发送必须保持独立语义。最近线程逐项包含标题、工作空间、状态和活动时间；自然命中目标时只追加柔和选中面和“当前”标记，不得使用多重强调，也不得把所有运行中线程标成当前。
3. 回复 `1`–`4` 应接管图片中对应线程；接管前必须重新读取线程并复核受信任工作空间。首页五分钟过期后旧编号必须拒绝，不得进入 Codex 提示词。
4. 验证 `5` 全部线程、`6` 新建、`7` 执行与队列、`8` 工作空间和 `9` 刷新；重新发送 `/` 后直接验证 `11`–`43` 的 15 项稳定能力，不得要求先进入二级目录。
5. 打开“微信可用命令”，目录必须只覆盖 17 个原生或适配命令；逐项执行必须进入真实类型化控制器。CLI、TUI、Windows 与实验协议专属命令不得出现在任何菜单；注册表覆盖与直接输入边界另行测试，未知斜杠输入不得进入 Codex 提示词。
6. 验证置顶、永久删除及其二次确认；永久删除父线程时 Codex 与本地索引中的所有派生线程同时消失。
7. 在桌面端、CLI 与 IDE 分别创建线程，`12` 必须跨来源显示所有位于受信任工作空间的线程；本地焦点索引中没有的线程也必须可接管。工作目录越界、删除或无法解析的线程必须隐藏并在接管复核时拒绝。
8. 发送“线程关系图”，应只收到一张 1080×1180 图片：最多一个父线程、当前目标、最多五个直接子线程和明确截断数量。图中不得出现正文、摘要、差异或文件信息；回复节点编号时必须重新读取线程并复核受信任工作空间，关系图生成后移出白名单的节点必须拒绝接管。
9. 切换默认工作空间不得隐藏其他白名单工作空间中的全局线程；已入队请求仍使用创建时冻结的工作空间和目标线程。`24` 必须汇总所有工作空间的技能与全局 MCP 摘要。
10. `codex-link-clawbot config` 必须显示有效的版本 6 脱敏摘要，不出现 API 密钥、锁码或 Codex 环境变量值；旧扁平、v2–v5、`message_interval_seconds` 和 `codex.cwd` 必须导致运行时启动失败。
11. `32` 或 `/review` 必须调用原线程 inline 审查并返回宽 1080、高 920–1502 的专用卡；带 `P0`–`P3` 的结论只展示前三项，绝对路径缩为末两级。卡片只可加入工作树文件/增删行、最近结构化验证结果和同线程交付可用性聚合，不得出现文件名、原始命令、终端输出或差异。无标准优先级且无明确“未发现问题”措辞时必须显示“结论需阅读”，不得冒充通过。
12. 分别点击“继续修复”“接受结论”“重新审查”：继续修复应以原工作空间和原线程入队，重新审查应再次进入原线程，接受结论不得提交、推送或部署；随后切换界面目标不能改变这三个动作的冻结目标。30 分钟内“文字版”应返回原生完整结论，审查正文不得进入 `control-state.json`。

## 2. codex-link-clawbot 持久请求队列

1. 启动一个长 Codex 轮次，连续发送两条文字、一张图片和一个 PDF；四项都应先成为 codex-link-clawbot 请求，在确认前落盘、只入队一次并按全局先进先出顺序执行。
2. 忙碌期间切换项目入口、线程、回答方式和视觉风格；旧请求使用入队快照，新请求使用新选择。
3. Codex 轮次执行期间发送“追加指令 先修复失败测试”，内容必须追加到同一轮次，不能创建新轮次；没有活动轮次时必须明确拒绝。
4. “请求队列”每页显示 6 条执行记录，按状态提供移到最前、删除、暂停、继续、取消、重试或取回冻结文字；清空队列必须二次确认且只影响当前绑定者的等待请求。
5. 暂停一个绑定者不应阻塞其他绑定者；远程锁定会取消 codex-link-clawbot 当前执行并暂停该绑定者，解锁后不得自动恢复。
6. 重复投递相同 `message_id` 或 `seq` 不得创建第二项，也不得再次下载附件。
7. 分别在 `queued`、`running`、`delivering` 阶段终止进程：等待请求继续排队，执行中和发送中请求转为人工处理中断，不得自动重复 Codex 轮次或整批消息。
8. 详情不得展示完整问题、回答、附件名、原始账号 ID、消息上下文令牌、终端输出或私有路径。
9. 长轮次阶段必须只来自当前 `turnId` 的 `turn/started`、`item/started`、`turn/plan/updated` 与 `turn/completed`；说明消息、命令输出、终端交互和差异不能产生进度。
10. 重复的开始、工作项类型和相同计划快照只能显示一次；同线程其他轮次事件必须忽略，不能混入当前请求。
11. 默认首条阶段门槛内只发送最新真实阶段，门槛后只在阶段签名变化时发送；无论执行多久都不得按固定时间重复“仍在执行”。
12. 完成、失败和中断必须冻结阶段报告；迟到阶段不可越过最终回答、失败说明或取消回执，微信阶段发送失败也不得影响 Codex 轮次。

## 3. 投递事务

1. 明确拒绝发送时轮次进入 `failed/delivery_failed`；响应丢失或部分媒体可能可见时进入 `interrupted/delivery_ambiguous`，两者恢复说明必须不同。
2. Codex 完成后必须先冻结正文、图片 URL、视觉风格、回答方式和交付物哈希，再进入 `delivering`。
3. 成功或取消后立即清理请求和结果；失败或中断负载最多保留 24 小时。
4. 语音模式必须先完整预上传阅读卡和 MP3，再依次发送；超长回答先发完整阅读卡，再发明确标注的语音节选卡与 MP3。
5. TTS、渲染或预上传在可见发送前失败时降级为完整阅读卡，再失败则发送全文；发送结果不确定时不得盲目补发。
6. 回答方式和视觉风格重启后保持；`preferences.json` 的未知字段、非法枚举、旧版本和尾随数据必须拒绝启动。
7. 普通阅读模式的多张回复也必须整批预上传后再发送；第二张预上传失败时第一张不得可见并应降级全文，第一张已可见后第二张发送响应不确定时不得补发全文。

## 4. 图片与交付

1. 图片和文件在排队时写入 `~/.codex-link-clawbot/tasks/<task>/inbox`；Codex 执行时图片以 `localImage` 输入，文件只作为不可信附件引用。
2. 要求 Codex 生成文件，微信收到后“交付箱”应出现私有副本；轮次临时目录清理后仍能再次发送。纯链接不得写入交付箱，必须作为普通请求交给 Codex。
3. 严格 v3 交付记录必须包含工作空间、Codex 线程、codex-link-clawbot 请求和 SHA-256；详情与最近结果显示相同来源。再次发送前重新校验摘要，副本缺失、大小变化或摘要不一致时明确显示“已失效”，不提供发送动作，也不重跑请求。
4. 交付记录超过每个绑定者 50 条时，被淘汰元数据和私有文件必须一并删除。运行时必须拒绝 v1/v2；离线迁移应清空旧元数据和旧私有副本并创建空 v3，部署失败时快照可整体恢复。
5. 图片批注必须生成新 PNG，不覆盖原图；长回复按所选刊物、构筑、黑标、可爱或简洁风格生成阅读卡，“文字版”可取回全文。
6. 无标题短回复不得虚构大标题；单页不得显示页码或进度条，多页只在第一页显示大标题、只在最后一页显示“文字版”入口，发送后不得追加重复说明文字。
7. 任务清单、2–4 列 Markdown 表格、超长表格单元格和代码块必须保持结构且无截断；阅读图高度应随内容在 720–2200 像素间收敛，典型混合回复不能把一个短代码块单独挤到尾页。

## 5. 类型化控制路由

1. 默认自然语言短语必须由 Intent Registry 唯一解析；重复 ID、规范化后重复短语、跨意图前缀覆盖和重叠前缀必须在注册时失败。
2. 普通 Codex 文字不得被控制层捕获；图片或文件消息只有在意图显式允许附件时才能触发控制动作。
3. 自然语言和数字菜单必须进入同一组领域控制器；跨领域大路由以及 `controlDispatches`、`controlRetries`、`controlFrozenTexts`、`controlMedia`、`controlVoice` 必须不存在。
4. 每项结果必须包含有效 action ID 和领域；空文字、缺少副作用参数、未知副作用和携带隐藏值的语音动作必须在发送微信前拒绝。
5. 请求重试、冻结文字、媒体和语音只能通过 Presenter 执行。非持久控制动作的回执发送失败不得导致状态动作被微信重投再次执行。

## 6. 持久交互与控制回执

1. 打开全局工作台或任意数字菜单后重建 `Handler` 并重新加载状态文件，原编号仍能执行；新 view 必须生成不同 revision。
2. 线程新建、改名和搜索的待输入状态在重启后继续；过期数字、返回和翻页必须明确拒绝且不得进入 Codex。
3. 严格 v14 `control-state.json` 只允许保存 revision、view、模式、过期时间、显式编号和受限 action 参数；卡片正文、标签、提示词、回答、路径、附件名、令牌和 `context_token` 不得出现。重复编号、v1–v13 运行时读取和未知版本必须拒绝。
4. 同一 revision 的并发回复最多一个成功；有副作用数字动作必须把 revision 消费和来源回执放在同一个原子文件事务。
5. 重复来源键不得再次创建线程、切换状态、删除、取消、复用请求、重试、发送媒体或生成语音；同一来源键映射到不同动作必须拒绝。
6. 修改状态的消息缺少稳定 `message_id` 与 `seq` 时必须失败关闭。回执只保留最小哈希身份和 action 元数据，24 小时后过期。
7. 成功请求复用和请求重试若在持久入队或确认阶段失败，必须删除控制回执并恢复原 revision；重投仍由请求来源键保证最多一个队列项。

## 7. 统一状态内核

1. 偏好、工作空间选择、远程锁、Codex 线程、待阅通知、交付箱、微信游标、codex-link-clawbot 请求队列 JSON、配置和账号凭据不得再包含独立的 `CreateTemp + Rename` writer。
2. 分别在 write、文件 sync、rename 和目录 sync 注入失败，旧文件必须仍可严格读取；内存状态不得声称未提交的新值。
3. 文件和目录权限分别收紧为 `0600`、`0700`；目标、临时项或任一路径祖先为符号链接时必须拒绝，且不得穿过链接创建文件。
4. 未知字段、尾随数据、截断 JSON、错误版本和超限文件必须分别归入稳定的 `schema`、`corrupt` 或 `capacity` 分类。
5. 服务持有状态锁时离线迁移必须返回 `conflict`；服务停止并释放后，同一迁移必须可以执行且保持幂等。
6. 无版本账号凭据只允许由离线迁移转换为严格 v1；运行时不得兼容或双写旧格式，损坏凭据不得静默跳过。
7. 私有备份清单的路径、大小和 SHA-256 必须稳定；修改任一备份文件后校验必须失败。

## 8. 游标、健康与排空

1. 入队写盘失败时不得推进微信同步游标；恢复磁盘后同一消息可以成功入队。
2. 一批消息中前项成功、后项失败时，私有消费回执应避免重做前项，同时保留整批旧游标。
3. `codex-link-clawbot status` 必须通过私有 Unix socket 返回严格结构化状态，包括版本、运行状态、Codex、微信监控、轮次数与排空状态；不得回退到 TCP 健康接口。
4. 排空期间仍可接收和持久化消息，但 Coordinator 不领取新任务。只有运行、发送、staging 和待提交同步批次都为零时 `drain_complete=true`。
5. 健康、排空、恢复和部署提交只存在于当前用户拥有的 `~/.codex-link-clawbot/control.sock`；socket 必须为 `0600`，TCP `/health` 与 `/admin/*` 必须返回 404。

## 9. 确定性无回复诊断

1. 发送“为什么没回复”或从运行中心选择同名入口，必须由系统控制器直接处理，不得创建 Codex turn；远程锁定时该入口仍可使用。
2. 诊断按固定优先级识别远程锁定、排空或停止、Codex 未就绪、微信监控异常、两分钟无成功轮询、超过 30 秒的待提交批次、15 分钟内的持久化错误、队列暂停、执行或发送、等待以及 24 小时内的失败或中断。
3. 当前诊断消息自身所在的待提交批次不得被误报为阻塞；没有确定性依据时必须明确说明无法断言，不能编造网络、Codex 或微信原因。
4. 登录过期、服务端非零 `ret` 或非零 `errcode` 必须把微信监控标记为不健康，且不得刷新最近成功轮询时间。
5. 回复最多包含三条依据和三个建议，不得出现绑定者 ID、问题正文、回答、附件名、文件路径、URL、令牌、环境变量、原始错误或命令输出。

## 10. 本机管理与受限通知

1. 配置和启动过程不得创建 TCP 监听；`api_addr`、`CODEX_LINK_CLAWBOT_API_ADDR`、`start --api-addr`、`send_api`、`codex-link-clawbot send` 和 `codex-link-clawbot send-token` 必须不存在。
2. 健康、排空、恢复和部署提交只注册在当前用户拥有且权限为 `0600` 的 Unix socket；部署通知请求不能携带自由正文、媒体、收件人或 URL，成功应返回 `deferred`。
3. 没有新微信消息时不得主动发送。固定格式部署完成事件和长任务恢复提醒只能写入严格 v1 `pending-notices.json`，且不得保存 `context_token`。
4. 待阅通知按绑定者隔离、去重、最多保留 32 条且最长 30 天；绑定者下一次有效交互最多合并补送四条。明确发送失败必须保留，响应不确定必须删除以抑制重复。

## 11. 事务部署与回滚

1. `update`、`upgrade`、daemon、PID 文件和 `scripts/cutover-local.sh` 必须不存在。
2. 发布部署使用 `codex-link-clawbot deploy <version>`；本地构建使用 `codex-link-clawbot deploy --binary /absolute/path --expect-version <version>`，候选必须自证精确版本和 Linux 架构。
3. 发布物必须通过 `checksums.txt` 的 SHA-256；任何下载、校验或版本错误都不得排空或替换服务。
4. 旧服务排空并停止后才创建一致状态快照和运行离线迁移。新服务先以排空模式启动，健康验收前不得领取旧队列。
5. 目标版本就绪后，systemd 单元不得残留 `--foreground` 或 `--draining`；队列显式恢复，固定格式部署事件写入待阅状态并在下一次有效交互中补送。
6. 注入迁移失败、启动失败或版本不符，必须恢复旧二进制、systemd 单元、配置、同步游标和完整任务状态，并验证旧版本重新 `ready`。
7. 部署收据不得含正文、令牌或附件名；成功后立即删除包含私密任务负载的状态快照。

## 12. 结果续接与模板移除

1. 运行时不得存在 `internal/workflow`、模板 Store、参数收集模式、模板 Intent、菜单 action 或“保存为提示词模板”入口。
2. `projects[].quick_tasks` 必须由严格配置解码拒绝且不得被改写；离线迁移只销毁当前命名空间中的 `~/.codex-link-clawbot/workflows.json`，不得导入、双写或保留兼容读取。
3. 控制状态必须升级为严格 v14，并在离线迁移中清空 v1–v13 的菜单和回执，旧目标线程管理编号、`8 全部功能` 或项目关注数字操作不得继续执行。
4. 成功纯文字请求只可保留严格 v1 `reusable.json`，其中只有原始请求；`context_token`、来源键、附件元数据、Codex 回答、交付物和终端输出不得出现。
5. 成功附件请求必须删除整个私密负载；纯文字复用副本超过 24 小时、请求记录被删除或终态记录淘汰后也必须删除。
6. 成功执行记录按能力只展示继续原 Codex 线程、再次执行和在新线程执行；缺失线程或复用副本时不得显示伪入口。
7. 原线程再次执行必须冻结请求的项目和线程；新线程执行必须冻结项目并显式保持空线程，不能读取界面当前线程。
8. 自然语言重跑若入队失败必须删除控制回执；微信重投仍由请求来源键保证只生成一个轮次。
