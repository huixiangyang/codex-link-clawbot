# 当前生产切换与真机验收

更新日期：2026-08-14

本文描述配置 v6、控制状态 v15、交付库 v3、纯数字全功能首页、线程关系图和真实轮次阶段的破坏性生产切换。日常部署仍使用 `codex-link-clawbot deploy`，不为旧品牌、旧配置、旧菜单、旧交付来源、斜杠输入、定时重复进度或项目监控保留运行时兼容。

## 1. 变更边界

- 配置破坏性切换为 v6 和 `codex-link-clawbot` 顶层键；旧配置不自动转换，`message_interval_seconds` 已删除。
- 删除 `project_watches`、`service_name`、`health_url` 和整个项目监控运行时。
- 删除 `automation-state.json`、`project-watch-state.json`、`scheduled-reports-state.json` 及 `project_watch` 待阅通知。
- 控制状态升级为 v15，v1–v14 旧菜单与回执清空。
- 交付库从 v1/v2 重置为空 v3；旧 `deliveries/` 私有副本因缺少线程、请求与摘要来源而销毁。
- 首页使用最近线程、五个高频动作和 15 个稳定数字直达；17 个细分 Codex 操作只在编号 `25` 下出现。
- 目标线程页加入一层原生关系图入口；图中编号接管前再次校验受信任工作空间。
- 长任务只按当前 `turnId` 的结构化 App Server 通知呈现阶段；重复签名和终态后的迟到事件被丢弃。
- 有效配置只留在诊断中心；按需语音播报只留在最近结果中心。

Codex 历史、工作空间选择、目标线程、请求队列、偏好、账号凭据、微信游标、部署通知和长任务恢复通知不应丢失。旧交付箱是本次明确销毁的唯一现存业务缓存；失败回滚时由事务快照恢复。

## 2. 停止条件

出现下列任一情况立即回滚：

- 候选版本、架构或 SHA-256 与记录不一致。
- 旧服务无法排空，或仍有运行、发送、暂存、待提交同步批次。
- 状态快照缺失或清单校验失败。
- 离线校验后配置不是严格 v6、控制状态不是严格 v15、交付库不是空 v3。
- 任一已删除监控状态仍存在，或 `pending-notices.json` 仍包含 `project_watch`。
- 候选 Codex、微信监控、Unix socket、队列数量或版本不符合基线。
- 真实微信出现确认后丢失、重复执行、跨工作空间越权或多媒体部分发送。

## 3. 窗口前验证

- [ ] 冻结当前开发分支，记录候选版本、commit、SHA-256 和构建时间。
- [ ] 执行 `make check`、配置模糊测试、竞态测试与 Linux amd64/arm64 构建。
- [ ] 复制最新生产状态到隔离临时目录，使用候选执行一次离线迁移。
- [ ] 对迁移后配置执行严格解析，并确认 `codex-link-clawbot config` 输出 schema 6。
- [ ] 确认工作空间只包含 `id`、`name`、`root`。
- [ ] 确认控制状态为 v15 空状态，三类监控状态文件不存在。
- [ ] 确认交付库为 v3，旧交付元数据和旧 `deliveries/` 私有副本不存在。
- [ ] 确认旧 `workflows.json`、`quick_tasks` 和所有项目监控字段均不存在。

隔离状态不得启动微信轮询；候选不得覆盖唯一的旧二进制副本。

## 4. 切换顺序

1. 使用当前二进制请求排空，确认 `drain_complete=true`。
2. 停止 systemd 用户服务，确认状态独占锁已释放。
3. 备份二进制、systemd 单元和完整状态根，并生成路径、大小和 SHA-256 清单。
4. 运行候选的 `migrate-state --root <state-root>`。
5. 使用候选严格解析当前配置；检查配置 v6、控制状态 v15、`message_interval_seconds` 已移除和监控状态删除结果。
6. 安装候选，以 `start --draining` 启动并通过私有 Unix socket 验证健康。
7. 核对精确版本、Codex 就绪、微信监控健康、队列数量、同步状态、工作空间、偏好和目标线程。
8. 移除 `--draining`，恢复正常服务并等待 `ready`。
9. 开始真实微信最小验收。

任何步骤失败都必须同时恢复旧二进制、systemd 单元和完整状态快照，不能只回滚二进制。

## 5. 真实微信最小验收

### 5.1 首页与 Codex 全局

- [ ] 发送“菜单”，只收到一张包含最近线程、五个高频动作和 15 个稳定数字动作的首页图片。
- [ ] 验证 `11` 全局总览、`12` 全局线程、`13` 账号额度。
- [ ] `12` 内能够查看运行中、全部、搜索和归档线程，并接管桌面端或 CLI 创建的线程。
- [ ] 验证 `21` 工作空间、`22` 目标线程、`23` 模型权限、`24` 技能工具、`25` Codex 操作；目录不得出现客户端专属项。
- [ ] 从 `22` 或自然语言“线程关系图”打开单张关系图；验证父线程、当前目标、直接子线程、截断数量、刷新和编号接管，随后制造节点越界并确认接管拒绝。
- [ ] 工作空间页不得出现服务、健康检查、项目关注、提示词模板或收藏入口。
- [ ] 打开完整数字操作目录；逐项回复数字能够真实执行，页面不出现斜杠标识。

### 5.2 codex-link-clawbot 执行与远程层

- [ ] 验证 `31` 新建、`32` 审查、`33` 请求队列和 `34` 取消。

### 5.3 输入、交付和恢复

- [ ] 连续发送文字、图片和 PDF，三项只入队一次并按冻结上下文执行。
- [ ] 启动超过 15 秒的长轮次，确认开始、计划、工作项与最终回答阶段只在真实切换时更新；重复事件不产生“仍在执行”，完成后无迟到阶段。
- [ ] 验证阅读模式、语音模式、超长回答和“文字版”。
- [ ] 生成一个文件并确认进入交付箱；详情显示工作空间、短线程号、短请求号和 SHA-256 已校验，临时目录清理后仍可再次发送。
- [ ] 破坏测试副本后确认详情显示“已失效”，不再提供发送动作且不会重跑请求。
- [ ] `32` 审查卡片显示聚合变更、验证与同线程交付事实，不出现文件名、原始命令、终端输出、差异或私有路径。
- [ ] 触发部署完成待阅通知；没有新微信消息时不得发送，下一次交互补送且状态中没有 `context_token`。
- [ ] 从成功纯文字请求继续原线程、原线程重跑和在新线程重跑。

## 6. 稳定观察

切换后至少观察一个完整工作周期：

- [ ] 结构化健康持续为 `ready`，微信监控没有长时间不健康或待提交批次。
- [ ] 没有未知 schema、状态锁、权限、原子写入、投递歧义或队列重复错误。
- [ ] 不存在 `internal/reporting` 对应进程行为、监控状态回生或旧菜单编号。
- [ ] 部署通知收据为 `deferred`，下一次有效微信交互补送后记录被删除。
- [ ] 候选版本、二进制 SHA、迁移清单、真机结果和回滚证据已经记录。
