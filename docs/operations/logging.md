# 日志与排障

业务事实保存在 SQLite，运行诊断使用纯文本日志。执行结果与投递是否完成应以请求和回执为准，不能仅根据日志中的“已开始”“已连接”推断成功。

## 日志位置

```text
~/.codex-link-clawbot/logs/
  service.log
  service-<UTC轮转时间>.log
```

当前文件达到 10 MiB 或跨 UTC 日期后的首次写入时轮转，最多 5 份归档，归档最多保留 7 天。启动与轮转时触发清理，静默或停服期间没有额外定时清理。目录权限为 `0700`，日志为 `0600`，拒绝已有符号链接或非普通文件。

时间戳为 UTC，精确到微秒，带进程 ID 和模块标签。只有取得运行锁的服务进程写入，使用 Lumberjack 轮转，不要再对同一文件配置外部 logrotate 或让多个实例共用目录。

```bash
tail -n 200 -F "$HOME/.codex-link-clawbot/logs/service.log"
journalctl --user -u codex-link-clawbot.service -n 200 -f
```

脱敏后的输出同时写 stderr，systemd 收入 journal，其留存由系统独立管理。文件输出失败会向 stderr 报警并继续尝试后续写入；日志初始化失败可能只能在启动命令或服务管理器的 stderr 中看到。

macOS 由应用写同一实例日志，不依赖 `/tmp` 固定日志。仓库 Air 编译日志在 `tmp/build-errors.log`，不属于实例运行日志。

## 常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 管理令牌无效 | 在实际服务账号执行 `console`，确认地址、主机、实例和当前令牌一致；解锁码不是管理令牌 |
| 浏览器 `ERR_CONNECTION_CLOSED` | 先查本机回环 HTTP 是否可达，再查 HTTPS 代理、Tunnel、TLS 和浏览器代理；不是直接认定应用认证失败 |
| `status` 失败 | 检查进程、用户服务、运行账号和 socket 权限；CLI 查的是 Unix socket，不是公网域名 |
| 启动提示旧状态或迁移未完成 | 停服后按[离线迁移](migration.md)处理，不删除状态绕过检测 |
| 图片能力初始化失败 | 检查非 Snap Chromium 的实际可执行路径；不需图片时停服设置 `visual.enabled=false` |
| 消息因忙碌被拒绝 | 查看同一会话是否仍在准备、执行或首次投递；切换会话或等待，原拒绝消息不会补执行 |
| 线程不可用 | 检查归档状态、Codex 登录和可信目录，刷新或显式选择；不会自动换到另一会话 |
| 执行完成但没有微信结果 | 分别检查归档状态与投递回执；先网页读取，归档失败恢复保存，投递失败才重发 |
| 重投要求新上下文 | 先发菜单更新本进程的微信上下文，尤其在重启或超过 24 小时未收消息后 |
| 容量不足 | 查看输入、结果与在途预留；清理确认不再需要的已结束请求，不手工删库或有效文件 |
| 部署 `commit_uncertain` | 保留现场，按[部署边界](deployment.md#提交与回滚)前向确认，不自动覆盖旧快照 |

以默认端口诊断本机管理 HTTP，可在服务主机执行不携带令牌的请求：

```bash
curl -i http://127.0.0.1:18120/api/snapshot
```

预期为 401，表示命中了需要认证的管理 API，不代表 Codex 或微信已经就绪。端口有修改时使用实际配置；不要把令牌加入 URL 或粘贴到对外诊断记录。

## 脱敏与分享

应用不主动记录提示词、微信正文或 Codex 事件原文。当前令牌、解锁码、MiMo 密钥及敏感环境值额外屏蔽；常见认证字段、Bearer 值、URL 用户信息、查询串与片段会脱敏，换行转义、控制字符过滤，单条内容限制 16 KiB。

Codex stderr 和上游错误可能带入无法自动识别的私人内容，分享前仍需人工检查。二维码、`console` 和交互式配置输出不复制进服务文件日志，但终端历史、录屏和重定向文件仍有泄漏风险。

日志不进入业务备份或回滚，`artifacts prune` 不清理日志。部署回执和交付回执是数据库业务记录，不依赖诊断日志恢复。实现入口见 [logging](../../internal/platform/logging/writer.go)与[脱敏规则](../../internal/platform/logging/privacy.go)。
