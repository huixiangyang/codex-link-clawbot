# 破坏性迁移

本版本不兼容旧微信控制面。

## 自动迁移

事务部署中的离线迁移会把严格合法的 schema 6 单向改写为 schema 7，并新增：

```json
{"management":{"listen":"127.0.0.1:18120"}}
```

迁移不会猜测公网域名。候选版本完成健康检查并提交后，再填写 `management.public_url` 并重启服务。运行时只接受 schema 7，不包含 schema 6 兼容代码。

## 会被删除

离线迁移会删除 `control-state.json`。旧数字菜单状态、待输入参数和控制回执无法迁入 Web 管理 API，也没有保留价值。

旧微信短语不会报“命令已下线”，而是成为 Codex 用户输入。部署后应明确通知使用者只通过管理页面做控制操作。

## 不变状态

请求队列、工作空间选择、线程引用、回复偏好、交付记录、账号凭据和待阅通知沿用现有严格状态格式。首次启动会新增 `management-token`。

## 回滚

旧二进制不理解 schema 7。事务部署器会在离线迁移前同时快照二进制、单元文件、配置和状态；提交前失败会整体恢复，不能只替换二进制。
