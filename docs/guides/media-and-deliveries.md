# 微信文件与交付箱

## 轮次私有目录

每个进入 Codex 的轮次统一创建：

```text
~/.codex-link-clawbot/turns/turn-*/
├── inbox/
└── outbox/
```

根目录、轮次目录和两个子目录权限均为 `0700`，入站文件权限为 `0600`。消息桥接器持有目录生命周期：最终文字与附件发送完成后删除；下载失败、Codex 失败或微信发送“取消”时同样删除。

这是破坏性的新边界。系统不再从 Codex 回复中解析裸绝对路径，也不会发送工作区中的任意现有文件。

## 微信文件输入

处理器从 iLink `FileItem` 读取文件名、明文大小和 CDN 加密信息，在 60 秒下载期限内完成 AES-128-ECB 解密，然后按实际内容和扩展名双重校验。

约束：

- 单条消息最多 8 个文件。
- 单个文件最大 50 MiB。
- 图片与文件合计最大 100 MiB。
- 支持 PDF、ZIP、TAR、GZip、文本、日志、Markdown、JSON/YAML、补丁和常见源代码。
- 拒绝 ELF、PE 可执行文件、伪装 PDF/ZIP/GZip、扩展名不在白名单内的文件，以及文本扩展名下包含 NUL 字节的二进制内容。
- ZIP/TAR 不自动解压，任何入站脚本都只作为不可信数据交给 Codex，不由桥接器执行。

Codex 接收的提示中明确包含文件名、探测到的内容类型、大小和本机绝对路径。纯文件消息自动使用文件检查指令；文字与文件同时发送时保留用户原始指令。

## Codex 交付物回传

每个轮次的提示都会告诉 Codex 专属 `outbox` 绝对路径。需要回传文件时，只把最终交付物写入该目录。轮次结束后，处理器递归扫描常规文件并按顺序上传微信 CDN。

允许的交付物包括 PDF、Office 文档、ZIP/TAR/GZip、补丁、文本、日志、Markdown、CSV、JSON/YAML、图片和 MP4/MOV。单次最多 8 个、单个最大 50 MiB、总计最大 100 MiB；符号链接和不支持的类型拒绝发送。成功与失败结果都会追加到最终微信文字。

同一次成组交付会先完成整批微信 CDN 预上传，再按声明顺序发送消息。预上传阶段任一项目失败时不会发送已经预上传的前项，避免留下缺少上下文的孤立媒体；消息发送阶段仍受微信逐条接口限制，结果日志会明确失败发生在哪一项。

## 交付箱

成功发送的 Codex 交付物会先复制到 `~/.codex-link-clawbot/deliveries/<owner-hash>/` 的 `0600` 文件，再删除轮次临时目录。微信发送“交付箱”或打开首页 `41` 可分页查看元数据。严格 v3 `~/.codex-link-clawbot/library.json` 把每条记录固定到工作空间、Codex 线程、codex-link-clawbot 请求和文件 SHA-256，按绑定者隔离且最多保留 50 条；达到上限时同时删除被淘汰记录的私有副本。界面只显示短线程号和短请求号，不展示私有文件路径。

交付详情在再次发送前重新检查常规文件、大小和 SHA-256。副本缺失、大小变化或摘要不一致时，记录仍会显示但明确标为“已失效”，不再提供再次发送，也不会静默重跑原请求。最近成功结果使用同一工作空间和线程来源，并显示微信交付状态。

v3 是破坏性边界：离线部署迁移会销毁 v1/v2 交付元数据和 `deliveries/` 中无法补齐线程、请求与摘要来源的旧私有副本，然后创建空 v3 交付箱；事务部署失败时仍由部署快照整体回滚。

纯链接不再由 codex-link-clawbot 旁路归档，也不会写入交付箱；它会和其他普通文本一样进入 codex-link-clawbot 请求队列并交给 Codex。

codex-link-clawbot 不提供 Git、systemd 或 HTTP 项目监控，也不维护定时关注状态。需要检查项目时，用户在目标 Codex 线程中发起普通请求；结果按本页的交付规则返回。
