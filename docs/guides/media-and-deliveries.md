# 微信文件、素材、交付物与自动化

## 轮次私有目录

每个进入 Codex 的轮次统一创建：

```text
~/.weclaw/turns/turn-*/
├── inbox/
└── outbox/
```

根目录、轮次目录和两个子目录权限均为 `0700`，入站文件权限为 `0600`。消息桥接器持有目录生命周期：最终文字与附件发送完成后删除；下载失败、Codex 失败或微信发送“取消”时同样删除。

这是破坏性的新边界。系统不再从 Codex 回复中解析裸绝对路径，也不会发送工作区中的任意现有文件。

## 微信文件输入

处理器从 iLink `FileItem` 读取文件名、明文大小和 CDN 加密信息，在 60 秒下载期限内完成 AES-128-ECB 解密，然后按实际内容和扩展名双重校验。

约束：

- 单条消息最多 8 个文件。
- 单个文件最大 50 MiB。
- 图片与文件合计最大 100 MiB。
- 支持 PDF、ZIP、TAR、GZip、文本、日志、Markdown、JSON/YAML、补丁和常见源代码。
- 拒绝 ELF、PE 可执行文件、伪装 PDF/ZIP/GZip、扩展名不在白名单内的文件，以及文本扩展名下包含 NUL 字节的二进制内容。
- ZIP/TAR 不自动解压，任何入站脚本都只作为不可信数据交给 Codex，不由桥接器执行。

Codex 接收的提示中明确包含文件名、探测到的内容类型、大小和本机绝对路径。纯文件消息自动使用文件检查指令；文字与文件同时发送时保留用户原始指令。

## Codex 交付物回传

每个轮次的提示都会告诉 Codex 专属 `outbox` 绝对路径。需要回传文件时，只把最终交付物写入该目录。轮次结束后，处理器递归扫描常规文件并按顺序上传微信 CDN。

允许的交付物包括 PDF、Office 文档、ZIP/TAR/GZip、补丁、文本、日志、Markdown、CSV、JSON/YAML、图片和 MP4/MOV。单次最多 8 个、单个最大 50 MiB、总计最大 100 MiB；符号链接和不支持的类型拒绝发送。成功与失败结果都会追加到最终微信文字。

同一次成组交付会先完成整批微信 CDN 预上传，再按声明顺序发送消息。预上传阶段任一项目失败时不会发送已经预上传的前项，避免留下缺少上下文的孤立媒体；消息发送阶段仍受微信逐条接口限制，结果日志会明确失败发生在哪一项。

## 素材与交付中心

纯链接由 Linkhoard 保存成功后，同步写入严格 v1 的 `~/.weclaw/library.json`。成功发送的 Codex 交付物会先复制到 `~/.weclaw/deliveries/<owner-hash>/` 的 `0600` 文件，再删除轮次临时目录。微信发送“素材箱”或“交付记录”可分页查看元数据，交付物详情支持再次发送。记录按绑定者隔离，最多保留 50 条元数据；界面不展示私有文件路径。

## 确定性自动化

`weclaw.features.automations` 中每项绑定一个 `project_id`，按 `daily_at` 或 `every_minutes` 运行。调度器每分钟检查计划，不把检查交给 Codex。

可组合的检查：

- 当前 Git 分支或 detached HEAD。
- 未提交改动数量。
- 相对上游的领先和落后提交数。
- `commit_lookback_hours` 时间窗口内最多 8 条提交。
- `systemctl --user is-active` 返回的服务状态。
- HTTP 健康端点的状态码和最多 256 字节响应摘要。

这些信息直接来自本机命令和 HTTP 响应。服务名经过白名单校验，Git 命令使用参数数组执行，不经过 shell。每次结果生成稳定指纹和异常标记，`notify_on` 可设置为每次、仅异常、仅变化、异常或变化。

运行状态原子写入严格 v1 的 `~/.weclaw/automation-state.json`。通知目标是每个已登录 iLink 凭据中的绑定者；状态按自动化 ID 和绑定者隔离。

## 微信自动化中心

发送“自动化”或从“更多功能”进入自动化中心。

列表每页显示 6 个计划，并提供页码、总计划数、最近下次运行和“上一页/下一页”导航。详情展示项目、检查组合、通知策略、下次运行、上次运行和上次通知。

| 状态 | 含义 |
| --- | --- |
| `等待首次运行` | 尚无检查结果 |
| `正常` | 最近检查无异常 |
| `异常` | Git、服务或健康端点发现异常 |
| `发生变化` | 稳定指纹与前次不同 |

详情允许“立即检查”，执行的仍是同一组确定性检查，不是自由提示词。微信端不能修改项目路径、服务名、健康地址、检查类型、时间或通知策略。
