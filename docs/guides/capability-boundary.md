# Codex 与 WeClaw 能力边界

WeClaw 是把个人微信接到本机 Codex 的交付与控制层，不是 Codex 的另一个名字。微信菜单、状态卡和文档必须明确标注能力归属。

## Codex 原生能力

以下状态和操作由 Codex 应用服务拥有，WeClaw 只负责在微信中展示和调用：

| 概念 | 能力 | 事实来源 |
| --- | --- | --- |
| 线程 | 创建、恢复、搜索、命名、分叉、置顶、压缩、归档、删除 | Codex `thread/*` 接口 |
| 轮次 | 在某个线程中执行一次输入、追加指令、中断 | Codex `turn/*` 接口 |
| 模型与推理 | 模型目录、线程模型、推理强度 | Codex `model/list` 与轮次参数 |
| 审查 | 审查当前工作目录的未提交改动 | Codex 审查接口 |
| 技能与外部工具 | 技能发现、外部工具连接状态 | Codex 技能与外部工具接口 |

Codex 应用服务没有 WeClaw 配置中的“项目对象”。Codex 只接收工作目录。菜单里的“WeClaw 项目入口”是受信任目录白名单和当前目录选择；选定后，该目录才作为 Codex 工作目录使用。

微信界面也按此拆页：“WeClaw 项目入口”只展示目录白名单与确定性检查边界；“Codex 能力”只展示 Codex 返回的技能、外部工具、模型和线程入口，两者不再混在“执行环境”页面。

## WeClaw 增强能力

以下能力由本系统实现，不应称为 Codex 原生功能：

| 能力 | 作用 |
| --- | --- |
| 微信接入 | 接收文字、图片和受限文件，向绑定者发送结果 |
| 项目入口 | 限制 Codex 可进入的本机目录，并保存当前选择 |
| 请求队列 | 在 Codex 轮次创建前可靠落盘、去重、排队、暂停和恢复 |
| 执行记录 | 保存请求的排队、Codex 执行和微信发送状态 |
| 回复呈现 | 文字、阅读图、视觉风格、图片、文件和语音配对交付 |
| 提示词模板 | 按绑定者和项目入口隔离的可复用提示词 |
| 内容与自动化 | 素材、交付记录、受限自动化和语音简报 |
| 运行与安全 | 无回复诊断、远程锁定、排空、部署和状态检查 |

## 请求不等于轮次

一条普通微信消息先成为 WeClaw 请求。只有队列协调器领取它，并调用 Codex `turn/start` 后，才产生 Codex 轮次：

```text
微信消息
  → WeClaw 请求
  → WeClaw 请求队列
  → Codex 轮次
  → WeClaw 冻结结果与微信交付
```

因此：

- “等待中”表示 WeClaw 请求尚未创建 Codex 轮次。
- “运行中”表示请求已经启动 Codex 轮次。
- “发送中”表示 Codex 轮次已经结束，WeClaw 正在交付结果。
- “追加指令”只作用于正在运行的 Codex 轮次。
- “暂停队列”只影响 WeClaw 后续请求，不改变 Codex 的线程或历史。

## 微信菜单分区

| 分区 | 归属 |
| --- | --- |
| `1` Codex · 工作台 | 线程、模型、推理、目标、审查、技能与外部工具 |
| `2` WeClaw · 请求 | 请求、执行记录、取消、暂停和恢复 |
| `3` WeClaw · 回复 | 回答方式、视觉风格和语音简报 |
| `4` WeClaw · 功能 | 模板、素材、交付和自动化 |
| `5` WeClaw · 设置 | 有效配置、项目入口、回复、队列和锁定 |
| `6` WeClaw · 诊断 | 无回复诊断、运行状态、说明和刷新 |

内部持久标识也遵守同一边界：真正的 Codex 轮次使用 `turn.*`，WeClaw 队列使用 `queue.*`，Codex 线程使用 `thread.*`。旧的队列 `turn.*` 控制状态不会兼容读取。
