# 能力边界

## 微信只是一条 Codex 链路

绑定者发送的普通文字、图片和文件会被校验、持久化并送入当前 Codex 目标。微信不再承担控制台职责。

微信仅识别以下精确入口：

- `菜单`
- `Codex`
- `Codex 菜单`
- `Codex Link`
- `codex-link`

这些入口只返回连接状态、当前工作空间、目标线程短编号和管理页面地址，不执行任何管理动作。带图片或文件时，即使文本是这些词，也会作为完整 Codex 请求入队。

## 管理台拥有的能力

| 领域 | 当前操作 |
| --- | --- |
| 连接 | 查看微信监听与 Codex App Server 健康状态 |
| 工作空间 | 查看白名单、切换新消息的默认工作空间 |
| 线程 | 查看最近全局线程、新建线程、设为微信目标 |
| 队列 | 暂停、继续、取消当前任务、置顶或删除等待任务 |
| 回复 | 选择自适应、阅读或语音模式；选择视觉风格 |
| 交付 | 查看最近交付物和可用状态 |
| 运行态 | 排空、恢复、查看版本和任务计数 |
| 安全 | 启用或解除远程锁定 |

管理台不是远程 Shell，也不允许提交任意目录、命令或环境变量。工作空间始终来自本机配置白名单。

## 已删除的行为

下列输入没有保留兼容解释：`1`、`状态`、`取消`、`请求队列`、`线程列表`、`视觉风格`、`交付箱`、`为什么没回复`、`文字版`、微信斜杠命令。它们会像其他文本一样进入 Codex。

旧控制意图注册表、数字菜单状态、控制回执和 `control-state.json` 均已移除。迁移程序会直接删除旧控制状态文件。

## Codex 与桥接器的所有权

Codex 拥有真实线程和轮次。codex-link-clawbot 只保存：

- 受信任工作空间定义和每个绑定者的当前选择；
- 当前目标线程引用；
- 等待、执行、投递和终态请求记录；
- 回复模式与视觉风格；
- 交付物私有副本和运行状态。

目标线程只是下一条微信消息的目的地，不表示其他 Codex 客户端不能同时运行线程。
