# 工作台指南

一个实例只启用一个微信绑定。微信用于提交与继续工作，网页用于搜索、详细管理和取回成果；配置、凭据和服务生命周期由本机 CLI 管理。网页没有新工作提交框，系统没有等待队列、定时任务、审批流或团队权限。

## 提交与继续

普通文字直接提交到当前工作空间与会话；没有线程时，首条工作建立会话，后续消息沿用它。每条请求固定接收时的目标与回复偏好，之后切换会话不会转移已经接收的工作。新建或切换失败时保留原选择，迟到的线程创建也不会覆盖新的选择。

同一会话从附件准备到首次结果投递结束都占用执行位置，第二条工作立即拒绝，并提供刷新、打断、切换、新建入口。被拒工作不会排队或稍后执行，重复来源也不能在空闲后补执行。不同会话可以独立工作。

网页当前目标独立于列表分页。微信新建对话先准备目标，首条工作才创建 Codex 线程；网页新建会立即创建并选择线程。已归档、不可访问或不属于可信工作空间的线程不能成为工作目标。

## 附件草稿

图片和文件先进入草稿，即使附件消息同时带有文字也不自动执行：

1. 发送图片或受支持文件。
2. 发送处理要求，可继续补充说明。
3. 发送 `提交`，通过会话准入后才下载、校验附件并执行。

`草稿` 查看当前内容，`丢弃草稿` 清空。每个绑定一份草稿，固定首条附件时的目标；切换会话后不能把原草稿提交给新目标，应切回或丢弃后重建。忙碌或维护导致未接收时，草稿保留，必须再次显式提交。

草稿 30 分钟未补充会失效，重启也不会自动执行。最多 4 张图片、8 个文件引用、1 MiB 说明；实际下载时单图不超过 20 MiB、单文件不超过 50 MiB、附件合计不超过 100 MiB。Office 文档须先导出 PDF。语音输入依赖微信提供的转写；没有转写时需改发文字，不提供独立语音识别。

## 菜单与控制

| 输入 | 行为 |
| --- | --- |
| `#` 或 `/` | 打开首页 / 返回首页 |
| `#1` 至 `#6` | 选择当前页面选项 |
| `#7` / `#8` / `#9` | 上一页 / 下一页 / 退出菜单 |
| `停止` / `取消` | 请求打断当前观察到的执行，不需再次进入菜单确认 |
| `全文 编号` | 阅读已保存回答，每页 500 字 |
| `文件 编号` | 只取已保存文件与图片链接，不重发全文 |
| `继续会话 编号` | 选择该结果的原会话，后续消息才进入它 |
| `重发 编号` | 确认后重发原回答与文件 |

菜单入口只匹配单独的 `#` 或 `/`，允许首尾空白及对应的全角符号；选项编号仍须带 `#`，数字也可使用全角。裸数字属于对话或草稿内容。`/help`、路径和 Markdown 标题不会因包含这些符号而打开菜单。旧的“菜单”“Codex”等关键词入口不再保留，按普通文字处理；`#0` 不再是首页快捷键。

首页六项依次为新建对话、切换会话、工作空间、会话状态、最近结果、对话设置。列表每页最多四项；编号绑定展示时的业务 ID，而不是实时列表位置。菜单十分钟过期，过期或重启后的选择刷新首页，不执行旧动作。解锁页面中的输入只用于解锁，不进入 Codex 或草稿。

首页上方预览最多三个活跃会话，按最近活动倒序，包含准备、执行和发送中的本地请求，以及可信目录内 Codex 标为 active 的会话；相同会话合并。活动时间取 Codex 的 `recencyAt`（缺省用 `updatedAt`）与本地开始/执行完成时间的较新值，同时间按 ID 稳定排序。更多会话由 `#4` 查看，浏览不会切换目标。目录失败时保留已知本地状态并提示不完整，锁定页不显示预览。

配置图片能力时菜单优先发一张紧凑图片，失败回退同编号文字；关闭图片能力时直接发送文字。首页打开时更新预览，目录缓存最多三秒，不自动推送刷新。

## 回复与结果

新用户默认完整文字，每段最多 1200 字，文件按需取回；已有保存的偏好不覆盖。可选择简洁通知、阅读图或 MP3，管理台和菜单只允许保存已配置能力。简洁通知对长回答发送开头节选；长语音也明确标为节选，语音不依赖图片能力。

普通请求不发送“已开始处理”回执，当前会话的完成消息只展示回答正文。启用进度提示时，从准备阶段开始计时，默认超过 15 秒只提示一次“还在处理中”，完成、失败或取消后停止提示。真实阶段仍记录在网页请求详情中，不逐阶段向微信推送。

已切换会话时，迟到的完成消息保留来源工作空间、会话和 8 位请求编号。节选回答才附全文入口，有文件才附取回入口；其他操作可从最近结果进入。快捷操作也接受完整 ID。短编号冲突时拒绝操作，需从结果列表选择。编号不是权限凭据，取回仍检查所有者、锁定、有效期和去重。

部署成功不发送微信通知，当前版本与健康状态在网页管理台查看，详细部署回执保留在服务器。升级时清理旧的部署成功待发通知；执行失败、结果未送达等需要处理的事项仍保留通知，无有效微信上下文时在下一次收到消息后补送。

网页请求中心区分进行中、待处理、历史、全部，支持搜索和分页。详情可查看原始文字、附件名、执行状态、回答、文件和投递记录，不返回消息令牌或私有绝对路径。回答与文件先保存，再进行微信投递；微信发送失败不影响网页取回。

## 停止与恢复

| 状态 | 正确操作 |
| --- | --- |
| 正在准备或执行 | 打断该请求；只停止对应执行，不影响其他会话 |
| 打断未确认 | 刷新或再次打断，不能直接重跑；实际完成的成果仍保留 |
| 已进入结果收尾 | 等待保存和首次投递，不再接受取消 |
| 执行失败或中断，输入有效 | 显式重新执行，生成关联原请求的新记录 |
| 执行完成但归档失败 | 恢复保存原成果，不再次执行 Codex |
| 微信发送失败或未确认 | 优先网页取回，确认后重投已有成果 |
| 结果过期或主动清理 | 无法取回已删除内容，不靠重投恢复 |

停止不撤销已经发生的文件修改，也不丢弃草稿。重跑可能重复原执行的部分副作用；重投可能产生重复微信消息，二者均需明确确认，操作编号只防止同一次操作的网络重试重复生效。

进程重启不会自动重跑或重投：未完成执行标记中断，已完成成果保留，未确认发送标记待确认。微信重跑与重投需要本进程近期收到的真实微信上下文；重启或超过 24 小时未收消息时，先发送 `#` 或 `/` 更新上下文。网页读取和下载不依赖它。

某个附件丢失或损坏不影响保留期内的文字和清单，也不阻断其他完好文件下载；清单可见不等于文件可交付。下载校验所选文件，执行与投递校验完整的对应附件集合。

## 留存、清理与入口控制

草稿、输入、结果和历史使用不同期限，完整数值与容量见[数据与产物](../design/sqlite-storage.md#留存与容量)。后台按期清理，输入到期不会删除仍有效的结果，也不会为新工作静默删除未到期成果。

网页可确认清理已结束请求，释放输入、结果和记录名额；保留最小来源回执防止旧消息重跑。清理不可恢复，不影响 Codex 在项目目录中直接修改的文件。

排空停止新工作准入，让正在处理的工作收尾；恢复后不存在待执行积压。远程锁只限制微信工作入口，不隐式取消当前执行，网页仍可取回成果。配置解锁码和能力的方法见[配置指南](configuration.md)，真实流程验证见[验收](../operations/acceptance.md)。
