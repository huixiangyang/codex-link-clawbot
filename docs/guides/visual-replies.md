# 微信视觉操作卡片

## 目标与范围

微信端的 Codex 线程与执行能力，以及 codex-link-clawbot 请求队列、回复呈现、交付、运行信息、确认和错误结果统一显示为纵向 PNG 卡片。普通卡片宽度固定为 1080 像素，高度根据内容在 900–2400 像素之间计算；`/` 使用独立的 1080×780 艺术画布，顶部 390 像素组织会话与拓扑，其余区域直接展开 Codex 功能。

codex-link-clawbot 自己生成的结构化控制结果始终使用固定操作卡片。全局工作台、功能目录、线程关系图和移动审查在控制器中同时生成完整回退文字与结构化视图，投递层直接选择对应渲染器，不再解析回退文字来识别页面。达到配置阈值的 Codex 最终回答会先被解析成受限的标题、段落、列表、任务清单、表格、引用、分隔线和代码块，再分页进入独立阅读模板；Codex 返回的 HTML、Markdown 原文或网页地址都不会作为 HTML 进入浏览器执行。

微信图片本身不可点击，因此操作总览使用稳定编号和持久控制状态完成交互：

1. 用户发送“菜单”，codex-link-clawbot 读取当前目标、Codex 全局线程和微信请求队列。
2. 工作台只发送一张图片，不再追加重复说明文字；渲染或上传失败时才回退完整文本。
3. `1`–`4` 绑定本版图片中的最近线程；`5`–`9` 固定为全部线程、新建、执行队列、工作空间和刷新；`11`–`43` 的稳定动作也可从首页直接回复。
4. 首页数字绑定有效期为 5 分钟；其他对象列表、确认或待输入流程使用十分钟状态。
5. 用户回复编号、名称或筛选词，codex-link-clawbot 在原控制状态中继续处理；斜杠前缀输入明确拒绝；`0` 返回或退出。

首页稳定直达编号继续按范围固定：`1x` Codex 全局，`2x` Codex 工作空间，`3x` Codex 执行，`4x` codex-link-clawbot 远程，不再要求先打开二级“全部功能”。远程锁定、取消当前执行、清空队列、归档和永久删除仍保留独立确认。

| 领域入口 | 稳定直达编号 |
| --- | --- |
| `1` Codex · 全局 | `11` 全局总览、`12` 全局线程、`13` 账号与额度 |
| `2` Codex · 工作空间 | `21` 工作空间、`22` 目标线程、`23` 模型与权限、`24` 技能与工具、`25` Codex 操作 |
| `3` Codex · 执行 | `31` 新建工作、`32` 审查改动、`33` 请求队列、`34` 取消执行 |
| `4` codex-link-clawbot · 远程 | `41` 最近结果与交付箱、`42` 系统健康与诊断、`43` 呈现与安全 |

## 视觉系统

视觉层由五个统一语义骨架组成：全局工作台、线程关系图、控制卡、长回复阅读卡和移动审查卡。五套设计系统共享严格的内容结构与安全边界，但各自拥有独立的字体层级、轮廓语言、明暗参数和离线材质，不再按风格复制完整 HTML。工作台同时承担会话统筹和 Codex 命令入口，不依赖二级功能目录：

| 风格 | 设计语言 | 适合场景 |
| --- | --- | --- |
| 刊物 | 棉纸纤维、中文衬线、活版边界和克制砖红 | 长文本、分析与编辑语境 |
| 构筑 | 玄武岩矿物、无衬线网格和建筑荧光色 | 日常控制、状态与高密度操作 |
| 黑标 | 哑光黑卡、留白和香槟金属压线 | 演示、交付和强调结果 |
| 可爱 | 手工奶油纸、圆润轮廓和柔和压印色块 | 轻松交流、日常陪伴与低压力阅读 |
| 简洁 | 档案纸、盲压细线和纯粹信息秩序 | 专注操作、快速扫读与安静界面 |

发送“回答方式”可进入统一偏好中心，再选择“视觉风格”；也可以直接发送“视觉风格”“切换风格 刊物”“切换风格 构筑”“切换风格 黑标”“切换风格 可爱”或“切换风格 简洁”。切换成功卡本身就是新风格预览。视觉风格与回答方式按微信账号隔离，共同保存到严格 v1 的 `~/.codex-link-clawbot/preferences.json`；文件通过私有临时文件、同步和原子替换写入，权限固定为 `0600`，父目录固定为 `0700`。没有历史选择时使用“构筑”和“自适应”。旧 `visual-styles.json` 已删除且不会自动迁移。

每套风格再以服务进程的本地时区自动选择明暗主题，不依赖微信客户端设置，也不提供兼容开关：

- 07:00–18:59：明亮纸面或矿物画布、深色正文，适合日间环境光。
- 19:00–06:59：深色墨面、浅色正文和收敛对比，减少夜间眩光。

主题只通过画布、文字和语义色呈现，不再额外显示主题名称或渲染时间。工作台不设置页面级大标题、说明副标题、独立统计卡和当前目标面板。顶部信息带左侧使用 52 像素固定行高的纯单列会话：标题是第一视觉层，工作空间、时间、微信状态和 Codex 状态退到第二层；当前线程只使用柔和选中面与一个“当前”标记。五个操作合并为列表下方 36 像素微型命令带，不得复用会话行样式。右上使用 42 像素单行遥测带并列显示工作空间、全部线程、运行中和微信队列，遥测带下方由矢量轨道、状态节点与细网格组成线程拓扑；所有数值、节点编号和颜色必须来自本版数据。顶部信息带固定为 390 像素；其余区域使用三个等宽列面板完整显示 15 个稳定数字动作，面板内的中文主标签和两位编号保持稳定基线。CLI、TUI、Windows 和实验协议专属项不得出现。正文禁止密集分割线、玻璃透明和文字水印。

移动审查卡宽 1080 像素，高度按事实和问题数量在 920–1502 像素间收敛：顶部给出结论和最高优先级，中部冻结工作空间、目标线程和审查范围，并列展示变更、验证和交付事实；正文最多显示三个带 `P0`–`P3` 的重点问题，底部固定提供继续修复、接受结论和重新审查。变更事实只含文件数与增删行，验证事实只含命令类别、状态和退出码聚合，交付事实只含当前线程的可发送与失效数量。绝对路径在问题位置中缩为末两级；原始命令、输出、差异和文件名不进入卡片。没有标准优先级条目的审查输出显示“结论需阅读”，不会推断为通过。完整原文沿用 30 分钟“文字版”取回机制，不写入持久菜单。

线程关系图固定为 1080×1180：父线程、当前目标和最多五个直接子线程按纵向血缘层级排布，曲线只表达本次真实 `forkedFromId` 关系；编号、显式标题、状态、工作空间和截断数量全部来自当前快照，不使用对话预览补标题。当前目标不提供编号，避免把“保持当前”伪装成接管动作；底部仅保留刷新和全局线程两个 Lucide 操作。五套视觉风格共享同一空间构图与日夜语义，渲染失败或图片上传失败时回退完整关系文字。

各风格在保持自身设计语言的前提下按语义类型调整强调色，避免状态色破坏整体质感：

| 类型 | 场景 | 强调色 |
| --- | --- | --- |
| `home` | 主控制台 | 荧光绿 |
| `session` | 线程 | 靛蓝 |
| `progress` | codex-link-clawbot 请求队列与执行状态 | 青色 |
| `system` | codex-link-clawbot 功能、设置、诊断与 Codex 能力 | 金色 |
| `success` | 已完成操作 | 薄荷绿 |
| `warning` | 确认、错误和阻塞 | 珊瑚色 |

界面图标统一使用内联 Lucide 路径，不依赖图标字体、表情符号或外部资源。五张无文字材质图以 WebP 编译进二进制，由固定风格枚举转换为 `data:` URL；它们不是远程图片，也不接受用户路径。模板使用本机 Noto CJK 字体并提供系统回退。画面不使用玻璃拟态、霓虹渐变、无意义光晕、装饰仪表盘或生成式占位图。

普通控制卡宽度固定为 1080 像素，高度按内容在 900–2400 像素间计算。全局工作台固定为 1080×780；可读会话区域宽 500 像素，四条线程时仍完整收在顶部左侧，右侧由线程拓扑承担视觉表达。编号区自纵坐标 390 开始，三个等宽列面板分别容纳 5 个稳定动作；动作行高度 42 像素，中文动作作为主标签，两位数字作为等宽元信息，15 项必须在同一张图片中完成渲染。

工作台校验只接受最多四个最近线程、五个固定动作、三个命令分组和恰好 17 个唯一可用命令；命令状态只能是原生或微信适配。渲染回归测试必须额外从真实注册表生成预览，确保不可用命令不会泄漏到界面。

## 渲染链路

渲染器优先发现 Linux `~/.cache/ms-playwright` 或 macOS `~/Library/Caches/ms-playwright` 中最新的 Chromium / Chromium Headless Shell，其次尝试系统 Google Chrome。也可以在配置中写明绝对路径：

```json
{
  "schema_version": 6,
  "codex": {"command": "codex"},
  "codex-link-clawbot": {
    "reply": {
      "visual": {
        "enabled": true,
        "browser_command": "/absolute/path/to/chrome",
        "long_replies": true,
        "long_reply_min_runes": 900
      }
    }
  }
}
```

对应环境变量是 `CODEX_LINK_CLAWBOT_VISUAL_BROWSER`。推荐安装方式：

```bash
npx playwright install chromium
```

Snap Chromium 使用私有挂载命名空间，无法稳定访问 codex-link-clawbot 的渲染文件，因此不会被自动发现，显式配置时也会被拒绝。视觉功能默认开启；没有可用浏览器时服务拒绝启动。明确设置 `"enabled": false` 后，所有控制结果只发送原文字。

每张卡片的处理流程如下：

```text
控制器结构化 ActionResult
  → 读取绑定者的回答方式与 Style
  → 直接选择 Card / Workbench / Directory / ThreadMap / Review
  → 注入固定 Lucide 图标与编译内置 WebP 材质
  → html/template 自动转义
  → 私有 HTML + Chromium profile
  → 1080px PNG
  → 微信 CDN 加密上传
  → 删除整个本次渲染目录
```

代码审查使用单独的收敛链路：

```text
review/start（inline）
  → exitedReviewMode 原文
  → 严格识别 P0–P3 与明确无问题结论
  → thread/read 提取最近结构化验证结果
  → 受信任工作树与当前线程交付记录生成聚合事实
  → 私有路径缩写 + 最多三项移动摘要
  → 专用 Review 模板 + 当前 Style
  → PNG 交付 + 30 分钟原文缓存
  → 冻结工作空间和线程的后续数字动作
```

Codex 回复图片使用独立的出站链路，入站图片不会进入这套逻辑：

```text
用户发送消息
  → 持久队列调用 Codex
  → 冻结最终 Markdown 回复与回答方式
  → 解析并分页 Document
  → 渲染全部阅读 PNG
  → 整批完成微信 CDN 预上传
  → 按页发送给原用户
  → 保留 30 分钟可复制原文
```

渲染并发上限为 2，单次超时 12 秒，PNG 上限 12 MiB。Codex 阅读回复会先渲染全部页面，再把整组 PNG 完成微信 CDN 预上传，最后才按页发送；预上传阶段任何一页失败都不会让半组图片对用户可见，而是降级发送原始完整文字。发送阶段如果微信响应不确定，则按图片可能已经可见处理，不补发可能重复的全文。

## 回答方式与阅读卡

“自适应”是默认回答方式：达到 `long_reply_min_runes` 的最终回复会生成 1–10 张阅读卡，较短回复保持文字。“阅读”会让所有 Codex 最终回答优先进入阅读卡，不受自适应阈值与 `long_replies` 开关影响。“语音”会把不超过 2200 个字符的同一份可朗读正文同时渲染为专用阅读卡和 MP3；超长回答先交付完整阅读卡，再交付带明确截断说明的语音节选卡与 MP3，绝不静默丢掉剩余正文。

只有开头且不超过 36 字的一级 Markdown 标题会成为整组卡片标题；没有合适标题时正文直接进入视野，不虚构“Codex 回复”。正文以每页 40 个视觉容量单位分页，标题不会孤立在页面末尾，超长表格行和代码块都能安全拆页。任务清单使用 Lucide 勾选框，2–4 列 Markdown 表格在手机上按两列信息单元重排。页高依据标题、实际文本行、表格网格和代码行在 720–2200 像素间估算，避免短内容被拉成长图。

单页阅读图不显示 `1 / 1` 或进度条；多页只在第一页展示大标题，各页显示必要页码，只有最后一页显示“文字版”入口。图片发送后不再追加重复说明文字。阅读卡与控制卡始终使用同一用户选择的风格及自动昼夜主题。30 分钟内回复“文字版”“查看原文”或“复制原文”可取得最近一次完整可复制回复。这些短语始终由控制层消费并清除旧菜单；缓存过期时只返回明确提示，不会开启新轮次。

超过 40000 个 Unicode 字符、预计超过 10 页，或浏览器不支持文档模板时，回复保持完整文字。`long_replies=false` 只关闭自适应模式的长回复卡片，不覆盖用户显式选择的阅读模式。普通阅读回答和语音回答都使用整批 CDN 预上传；语音再按完整阅读卡、语音正文卡、MP3 的顺序发送。任何内容可见前失败时降级为完整阅读卡，再失败则发送全文。发送阶段响应不确定时按“可能已经可见”处理，不盲目补发重复正文。

## 安全边界

- 三个语义模板、五套主题别名和五张 WebP 材质全部编译进二进制，只接受预定义字段；不存在任意模板、任意资源路径或任意 HTML 接口。
- 所有动态文本由 Go `html/template` 自动转义。
- Markdown 只解析受限的展示结构，不启用内嵌 HTML、脚本、远程样式或 iframe。
- 页面 CSP 为 `default-src 'none'`，不包含 JavaScript，也不加载外部字体、样式或图片。
- Chromium 启动时关闭后台网络，并把所有主机名解析到不可达地址。
- 渲染根目录权限为 `0700`，HTML 和 PNG 权限为 `0600`。
- 每次渲染使用独立目录和独立浏览器 profile；上传成功、失败或上下文取消后全部删除。

```bash
go test ./internal/visual ./internal/bridge ./internal/config
go test -race ./internal/visual ./internal/bridge
go vet ./...
```

部署后依次切换刊物、构筑、黑标、可爱和简洁；每次重新发送“菜单”都应只收到一张对应风格的完整首页，15 个稳定动作编号清晰可读，对应 `/command` 作为只读 Codex 功能对照保留。验证 `11`、`12`、`13`、`21`、`22`、`25`、`31`、`33`、`41`、`42` 和 `43`，确认编号重启后仍有效、斜杠文本输入会拒绝、远程锁定只在配置后出现且必须二次确认、动态状态不改变编号。再依次切换自适应、阅读和语音，验证短回答、无标题回答、任务清单、2–4 列表格、超长代码、TTS 失败、第二页预上传失败与重启持久化。日间与夜间都应检查 Codex 能力、Codex 线程列表、codex-link-clawbot 请求状态、有效配置、交付箱和呈现安全。预期不出现主题名称、渲染时间、装饰计数、表情符号、单页页码、进度条或无意义水印；多页在第一张可见前应已完成整批预上传，阅读页和代码块均无截断，并可用“文字版”取回全文。临时渲染目录不应残留。
