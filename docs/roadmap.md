# codex-link-clawbot 产品路线

更新日期：2026-08-11

## 产品定位

codex-link-clawbot 是 Codex 桌面端在个人微信中的远程延续：外出时从全局视角查看本机 Codex 工作、接管目标线程并继续执行。它只支持 Codex 应用服务，不做通用机器人、多模型路由、项目监控、远程命令行或任意工作目录。

产品严格区分三类 Codex 原生概念：

1. 线程：可以持续、恢复、分叉和归档的对话。
2. 轮次：线程中的一次输入与执行。
3. 技能与工具：Codex 从工作目录和用户环境发现的能力。

工作空间白名单、远程目标焦点、微信持久请求队列、阅读卡、语音和交付箱属于 codex-link-clawbot 的移动接入层。Codex 没有 codex-link-clawbot 的项目对象；工作空间只限定远程文件与线程边界，不承载服务健康、定时检查或第二套知识库。

| 归属 | 领域 | 已实现 |
| --- | --- | --- |
| Codex | 全局线程 | 跨桌面端、CLI、IDE 与 App Server 的发现、搜索、运行筛选、接管、新建、重命名、分叉、置顶、压缩、目标、归档、恢复、永久删除 |
| Codex | 账号、模型与轮次 | 账号和额度、模型目录、线程级推理强度、真实轮次、追加指令和中断 |
| Codex | 审查与工具 | 原线程未提交改动审查、确定性变更与验证事实、移动审查结论卡、同线程继续修复、技能和外部工具连接摘要 |
| Codex | 命令面 | 官方 49 个主斜杠命令与 5 个别名由注册表识别；微信界面只展示 17 个稳定 App Server 原生或适配能力 |
| codex-link-clawbot | 输入与远程焦点 | 文字、最多四张图片、受限文件、隐式图片批注、工作空间白名单、全局工作台、默认空间和目标线程选择 |

| codex-link-clawbot | 诊断与安全 | 无回复诊断、运行状态、只读有效配置、远程锁定、排空和事务部署 |

微信首页已经重构为 1080×780 的 Codex 全功能画布。最近四个线程与 `5`–`9` 收在顶部左侧：会话标题是第一视觉层，工作空间、状态、活动时间与微信执行标记退居第二层，当前线程只增加柔和选中态和“当前”标签；操作使用列表下方的微型命令带，不再伪装成五条会话。右上以单行遥测带显示工作空间、全部线程、运行中和微信队列，真实线程拓扑从其下方展开，所有顶部内容共同限制在 390 像素。其余画布由三个等宽列面板直接显示 17 个微信可用命令。`11`–`43` 的 15 个稳定动作从首页直接执行，不再要求二级目录。页面不设大标题、说明区、独立统计卡、当前目标面板、表格边框或传统页脚。

## 已完成基线：全局远程工作台

完成标准：

- 全局目录直接读取 Codex 历史，不以本地微信焦点索引判断可见性。
- 所有线程展示和接管都执行工作空间路径边界校验，失败关闭。
- 账号、额度、模型、技能、MCP 与线程状态形成统一全局总览。
- 分叉、置顶、压缩、目标、模型、推理强度、轮次追加和代码审查都有协议测试与微信流程测试。
- Codex 菜单统一显示中文与规范 `/command`；注册表覆盖官方命令全集，微信目录只投影真实可用子集，直接输入和边界仍有独立测试。
- 首页保留一行服务状态、最多四个最近线程、五个高频操作、15 个稳定直达和 17 个微信可用斜杠命令；机器配置只在诊断中心出现，语音播报只在最近结果中心出现。
- 配置严格使用 v5，短期控制状态严格使用 v13；运行时不翻译旧品牌、旧字段、旧动作或旧编号。
- 完整测试、竞态检查、静态检查和构建通过后，才进入部署。

## 已完成阶段一：移动端审查事实

目标：让一次编码轮次在手机上快速判断“改了什么、是否可靠、下一步做什么”。

- 保留 Codex 原生 `review/start` 的结论、风险优先级和同线程继续修复。
- 从受信任工作空间补齐确定性变更文件统计、已执行测试和交付物状态。
- 不展示原始差异、终端输出、私有路径、账号或凭据。
- 不建设预览站点、浏览器 URL 白名单或自动前后截图系统；用户需要截图时作为普通 Codex 工作执行。

已完成：`exitedReviewMode` 结论被收敛成专用移动审查卡；`thread/read(includeTurns=true)` 只提取最近验证轮次的命令类别、状态和退出码，工作树只提取文件与增删行统计，交付箱只提取当前线程可再次发送与已失效数量。原始命令、终端输出、差异、文件名和私有路径都不进入卡片。卡片支持“继续修复”“接受结论”“重新审查”，完整原文只在绑定者显式回复“文字版”时短期取回。

完成门槛：审查卡只展示可验证事实，并能从卡片继续原 Codex 线程。

## 已完成阶段二：统一交付生命周期

目标：让审查卡、阅读图、图片和文件共享清晰的产生、引用、失效和再次发送语义。

- 交付记录只保存已经成功发送的私有文件副本。
- 最近结果与交付箱使用同一工作空间和线程来源信息。
- 失效交付物明确显示不可恢复，不静默重跑原请求。
- 语音是最近结果的一种按需交付形式，不形成独立内容中心。

完成门槛：用户可以从最近结果继续线程，也可以从交付箱稳定地再次发送仍有效的文件。

已完成：交付记录严格使用 v3，每条记录固定工作空间、Codex 线程、codex-link-clawbot 请求和 SHA-256；再次发送前重新校验私有副本。缺失、大小变化或摘要不一致的副本保留可见记录但明确标为“已失效”，不再提供发送动作，也不会重跑原请求。最近结果同步展示微信交付状态。

## 已完成阶段三：全局工作台

目标：让手机端打开首页就能判断当前目标、最近工作、Codex 并行执行和 codex-link-clawbot 请求状态。

- 全局事实直接读取 Codex 线程目录，不复制成 codex-link-clawbot 线程库。
- 当前目标、Codex 运行状态和微信执行状态分开呈现。
- 最近线程绑定只在五分钟首页 revision 内有效，接管时再次校验受信任工作空间。
- 17 个微信可用命令以三列矩阵直接进入首页；不可远程执行的命令不占据视觉空间，不使用分类分页。

完成门槛：`/` 只发送一张工作台图片；最近线程可直接接管；无目标、Codex 不可用和活跃微信请求都有明确状态；测试、构建与真机部署通过。

## 下一阶段四：线程关系图

目标：在不引入第二套项目或会话模型的前提下，让手机端看清 Codex 原生线程的分叉关系。

- 只读取 Codex 线程 ID、`forkedFromId`、标题、状态和受信任工作空间映射。
- 输出单张静态图片，明确当前目标、父线程、直接子线程和被截断数量。
- 从图片配套编号接管某一线程；接管时再次执行工作空间边界校验。
- 不缓存独立线程树，不自动修改线程，也不读取对话正文或差异。

完成门槛：用户可以从当前目标线程查看一层分叉关系，并安全接管仍存在且位于白名单内的节点。

## 候选功能

| 候选 | 价值 | 前置条件 |
| --- | --- | --- |
| 轮次阶段呈现 | 只在真实阶段变化时更新进度，减少噪声 | App Server 事件覆盖稳定 |
| 本机配置体检 | 离线检查浏览器、语音、Codex 和系统服务前提 | 当前部署流程稳定 |

## 明确不做

- Claude、Gemini、Kimi 或多模型提供商路由。
- 多智能体产品概念和跨智能体线程。
- 任意工作目录、任意命令或任意网址自动化。
- Git、systemd、HTTP 项目监控、定时关注、临时关注或项目仪表盘。
- 项目收藏、标签、显式项目记忆或另一套长期知识库。
- 预览站点管理、自动前后截图或浏览器 URL 白名单系统。
- 未经确认的提交、推送或部署。
- 群聊协作、默认永久记忆、伪原生语音气泡。
- 自定义伪斜杠命令、旧中文“会话/任务”入口和运行时兼容层。

## 功能进入规则

每个新功能必须先回答：它属于 Codex 原生全局线程、轮次、技能或工具，还是 codex-link-clawbot 的工作空间边界、请求队列、呈现或交付层；失败和部分成功如何展示；状态由谁拥有、保存多久；是否扩大文件、网络或凭据边界；如何自动测试、真机验收和回滚。无法明确回答时，不进入操作总览。
