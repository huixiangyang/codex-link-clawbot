# 微信视觉操作卡片

## 目标与范围

微信端的项目、菜单、会话、任务、自动化、素材、交付、运行信息、确认和错误结果统一显示为纵向 PNG 卡片。卡片宽度固定为 1080 像素，高度根据内容在 900–2400 像素之间计算，适合手机和平板直接阅读。

WeClaw 自己生成的结构化控制结果始终使用固定操作卡片。达到配置阈值的 Codex 最终回答会先被解析成受限的标题、段落、列表、引用、分隔线和代码块，再分页进入独立阅读模板；Codex 返回的 HTML、Markdown 原文或网页地址都不会作为 HTML 进入浏览器执行。

微信图片本身不可点击，因此交互仍由现有十分钟状态机完成：

1. 用户发送 `/` 或自然语言控制意图。
2. WeClaw 生成结构化卡片并上传微信 CDN。
3. 有数字选项或待输入内容时，再发送一条短文字提示。
4. 用户回复数字、名称或路径，WeClaw 在原控制状态中继续处理。

## 视觉系统

视觉层包含五套独立设计系统；每套都有自己的控制卡和长回复阅读卡，不通过通用模板套皮：

| 风格 | 设计语言 | 适合场景 |
| --- | --- | --- |
| 刊物 | 暖纸、中文衬线、发丝线和克制砖红 | 长文本、分析与编辑语境 |
| 构筑 | 平面石材、无衬线网格和建筑色 | 日常控制、状态与高密度操作 |
| 黑标 | 高对比黑白、留白和香槟金属细节 | 演示、交付和强调结果 |
| 可爱 | 奶油纸、圆润轮廓和柔和色块 | 轻松交流、日常陪伴与低压力阅读 |
| 简洁 | 高留白、发丝线和纯粹信息秩序 | 专注操作、快速扫读与安静界面 |

发送“回答方式”可进入统一偏好中心，再选择“视觉风格”；也可以直接发送“视觉风格”“切换风格 刊物”“切换风格 构筑”“切换风格 黑标”“切换风格 可爱”或“切换风格 简洁”。切换成功卡本身就是新风格预览。视觉风格与回答方式按微信账号隔离，共同保存到严格 v1 的 `~/.weclaw/preferences.json`；文件通过私有临时文件、同步和原子替换写入，权限固定为 `0600`，父目录固定为 `0700`。没有历史选择时使用“构筑”和“自适应”。旧 `visual-styles.json` 已删除且不会自动迁移。

每套风格再以服务进程的本地时区自动选择明暗主题，不依赖微信客户端设置，也不提供兼容开关：

- 07:00–18:59：明亮纸面或矿物画布、深色正文，适合日间环境光。
- 19:00–06:59：深色墨面、浅色正文和收敛对比，减少夜间眩光。

主题只通过画布、文字和语义色呈现，不再额外显示主题名称或渲染时间。卡片删除数据/操作计数、重复英文副标题、装饰网格与噪点、巨型页码水印、页脚内部编号，以及容易让人误以为图片可点击的箭头。页面只保留对判断状态或完成操作有直接作用的信息。

各风格在保持自身设计语言的前提下按语义类型调整强调色，避免状态色破坏整体质感：

| 类型 | 场景 | 强调色 |
| --- | --- | --- |
| `home` | 主控制台 | 荧光绿 |
| `session` | 会话与线程 | 靛蓝 |
| `progress` | 活动任务与任务记录 | 青色 |
| `system` | Codex、项目与自动化 | 金色 |
| `success` | 已完成操作 | 薄荷绿 |
| `warning` | 确认、错误和阻塞 | 珊瑚色 |

界面图标使用内联 Lucide 路径，不依赖图标字体、表情符号或外部资源。模板使用本机 Noto CJK 字体并提供系统回退。画面不使用玻璃拟态、霓虹渐变、无意义光晕、装饰仪表盘或 AI 生成式占位视觉。

控制卡宽度固定为 1080 像素，高度按内容在 900–2400 像素间计算。短状态值自动使用三列，长状态值回落为两列；至少四个且名称较短的操作使用双列，长操作使用单列。选项末尾的简短状态会拆为语义标签，原始交互文字保持不变。布局不再按条目数线性拉长，因此主控制台可以同时展示 6 个状态和 7 个入口而不产生大片空白。

## 渲染链路

渲染器优先发现 `~/.cache/ms-playwright` 中最新的 Chromium 或 Chromium Headless Shell，其次尝试系统 Google Chrome。也可以在配置中写明绝对路径：

```json
{
  "visual": {
    "enabled": true,
    "browser_command": "/absolute/path/to/chrome",
    "long_replies": true,
    "long_reply_min_runes": 900
  }
}
```

对应环境变量是 `WECLAW_VISUAL_BROWSER`。推荐安装方式：

```bash
npx playwright install chromium
```

Snap Chromium 使用私有挂载命名空间，无法稳定访问 WeClaw 的渲染文件，因此不会被自动发现，显式配置时也会被拒绝。视觉功能默认开启；没有可用浏览器时服务拒绝启动。明确设置 `"enabled": false` 后，所有控制结果只发送原文字。

每张卡片的处理流程如下：

```text
控制文本
  → 读取绑定者的回答方式与 Style
  → 结构化 Card / Document
  → html/template 自动转义
  → 私有 HTML + Chromium profile
  → 1080px PNG
  → 微信 CDN 加密上传
  → 删除整个本次渲染目录
```

渲染并发上限为 2，单次超时 12 秒，PNG 上限 12 MiB。图片生成失败或 CDN 上传失败时，处理器自动发送原始完整文字，控制状态不会丢失。

## 回答方式与阅读卡

“自适应”是默认回答方式：达到 `long_reply_min_runes` 的最终回复会生成 1–10 张阅读卡，较短回复保持文字。“阅读”会让所有 Codex 最终回答优先进入阅读卡，不受自适应阈值与 `long_replies` 开关影响。“语音”会把不超过 2200 个字符的同一份可朗读正文同时渲染为专用阅读卡和 MP3；超长回答先交付完整阅读卡，再交付带明确截断说明的语音节选卡与 MP3，绝不静默丢掉剩余正文。

第一个 Markdown 标题可成为整组卡片标题；正文以每页 32 个视觉容量单位分页，标题不会孤立在页面末尾，代码块保持换行和等宽字体。页高按实际正文量在 900–1900 像素间计算，短页减少无效留白，满页保留页脚安全区。阅读卡与控制卡始终使用同一用户选择的风格及自动昼夜主题。30 分钟内回复“文字版”“查看原文”或“复制原文”可取得最近一次完整可复制回复。这些短语始终由控制层消费并清除旧菜单；缓存过期时只返回明确提示，不会开启新 turn。

超过 40000 个 Unicode 字符、预计超过 10 页，或浏览器不支持文档模板时，回复保持完整文字。`long_replies=false` 只关闭自适应模式的长回复卡片，不覆盖用户显式选择的阅读模式。语音回答会先完成 TTS、全部图片渲染和整批 CDN 预上传，再按完整阅读卡、语音正文卡、MP3 的顺序发送；任何内容可见前失败时降级为完整阅读卡，再失败则发送全文。发送阶段响应不确定时按“可能已经可见”处理，不盲目补发重复正文。

## 安全边界

- 五套控制模板和五套阅读模板全部编译进二进制，只接受预定义字段；不存在任意模板或任意 HTML 接口。
- 所有动态文本由 Go `html/template` 自动转义。
- Markdown 只解析受限的展示结构，不启用内嵌 HTML、脚本、远程样式或 iframe。
- 页面 CSP 为 `default-src 'none'`，不包含 JavaScript，也不加载外部字体、样式或图片。
- Chromium 启动时关闭后台网络，并把所有主机名解析到不可达地址。
- 渲染根目录权限为 `0700`，HTML 和 PNG 权限为 `0600`。
- 每次渲染使用独立目录和独立浏览器 profile；上传成功、失败或上下文取消后全部删除。

## 验证

```bash
go test ./visual ./messaging ./config
go test -race ./visual ./messaging
go vet ./...
```

部署后依次切换刊物、构筑、黑标、可爱和简洁；每次成功卡应立即呈现所选风格，重启后保持。再依次切换自适应、阅读和语音，验证短回答、超长回答、TTS 失败、预上传失败与重启持久化。日间与夜间都应检查 `/`、项目中心、会话列表、任务状态、自动化详情、素材与交付和远程锁定。预期不出现主题名称、渲染时间、装饰计数、表情符号或无意义水印；6 条长选项、阅读页和代码块均无截断，并可用“文字版”取回全文。临时渲染目录不应残留。
