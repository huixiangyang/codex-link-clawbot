# WeClaw 整体产品与架构规划

更新日期：2026-08-05

## 1. 产品定位

WeClaw 是“个人微信里的本机 Codex 工作台”，不是通用聊天机器人，也不是多模型聚合器。所有能力必须服务于四条完整闭环：

1. 输入：微信文字、图片和文件安全进入一次 Codex turn。
2. 工作：项目、会话、任务和后续指令拥有明确状态，重启后仍可解释。
3. 交付：文字、阅读卡、图片、文件和音频按移动端最合适的形式返回。
4. 运维：状态检查、自动化、锁定、升级和回滚不依赖模型猜测。

明确不做多 Agent 路由、旧斜杠命令、任意工作目录、模型自动切换和不可验证的微信“伪成功”。

## 2. 当前产品结构

| 领域 | 当前能力 | 当前边界 |
| --- | --- | --- |
| 工作空间 | 项目白名单、项目切换、项目内快捷任务 | Codex 只能使用配置中的绝对目录 |
| 会话 | 新建、搜索、详情、切换、重命名、归档、恢复 | 会话按绑定者和项目隔离 |
| 任务 | 进度、取消、单条后续指令、最近记录、token 用量 | 同一绑定者同时只运行一个 turn |
| 输入 | 文字、最多 4 张图片、受限文件、图片批注 | 附件只进入本次 turn 私有目录 |
| 输出 | 自适应、阅读、语音三种持久回答方式，交付物与语音简报 | 原生出站语音不可用，音频走图片 + MP3 文件 |
| 运维 | 运行中心、确定性自动化、远程锁定、本地 API | 主动音频没有会话令牌时不可发送 |

配置中的 `voice.enabled` 表示语音能力可用，并要求视觉渲染同时开启。微信发送“发语音”只触发一次语音简报；发送“开启语音模式”则持久应用于后续 Codex 回答。“回答方式”与“视觉风格”统一保存在按绑定者隔离的严格 v1 偏好状态中。

## 3. 目标架构

```text
微信输入
  └─ 入站校验与私有附件目录
      ├─ 本机控制意图 ── 项目 / 会话 / 任务 / 偏好 / 运维
      └─ Codex turn ───── 单一 App Server 运行时
                            │
                            ▼
                       结构化交付计划
                      ├─ 文字
                      ├─ 阅读卡
                      ├─ 交付物
                      └─ 图片 + 音频批次
                            │
                            ▼
                      微信 CDN 预上传
                            │
                            ▼
                       确定顺序发送
```

关键调整是把“生成内容”和“发送消息”分开。多媒体交付必须先形成结构化计划并完成整批 CDN 预上传，再按顺序对用户可见；不能由各功能临时拼接发送步骤。

## 4. 路线与验收门槛

### P0：交付一致性

状态：已完成代码、集成测试与微信真机验收。

- 图片与 MP3 使用同一份播报稿。
- 专用单卡不显示单页页码、100% 进度和重复状态卡。
- 同一批媒体全部预上传成功后才开始发送；第二项预上传失败时第一项也不得出现。
- 日志必须区分生成、渲染、预上传和可见发送。

完成门槛：集成测试验证 `图片预上传 → 音频预上传 → 图片发送 → 音频发送`，并由真实微信确认两项均可见。

### P1：统一回答方式

状态：已完成实现与自动化验收，待本轮部署后进行微信真机回归。

- 新增按绑定者持久化的回答方式：自适应、阅读、语音。
- 自适应模式保留“短文字、长阅读卡”；阅读模式始终优先卡片。
- 语音模式使用同一正文渲染专用阅读卡和音频；超过 2200 个字符时先发完整阅读卡，再发带明确说明的语音节选卡与 MP3，不能静默截断。
- 回答方式与视觉风格进入统一偏好中心，菜单展示当前值，支持自然语言切换。

完成门槛：普通 Codex 回答、错误回答、带交付物回答和超长回答均有端到端测试，重启后偏好保持。

### P2：任务与升级可靠性

- 用持久任务队列彻底替换内存中的“单条暂存指令”；队列项固定绑定创建时的绑定者、项目、会话和附件副本，不受之后切换项目影响。
- 队列支持查看详情、调整优先级、删除、暂停和继续；同一 Codex 运行时先全局串行执行，禁止通过可变 `cwd` 伪造多项目并发。
- 服务进入排空状态后拒绝新 turn，等待当前可见回复结束再升级。
- 健康接口返回结构化版本、Codex 就绪、微信监控、任务队列和排空状态。
- 删除生产机器专用的硬编码切换脚本，收敛为可验证的 CLI 升级流程。
- `weclaw deploy` 必须自行完成排空、状态快照、二进制替换、重启、健康检查和失败回滚，不依赖调用者 PATH、当前目录或生产机脚本。

完成门槛：文本、图片和文件队列重启后保持；升级期间的入站消息不会被确认后丢失；回滚同时覆盖二进制、配置和状态 schema。

### P3：安全与可维护性

- 非回环地址启用本地 API 时必须配置认证，默认继续只监听回环地址。
- 将超大控制路由拆分为菜单路由、会话控制、任务控制和偏好控制；领域状态不再堆叠在 `Handler`。
- 统一私有状态文件的原子写入、权限、schema 校验和错误恢复策略。
- 为微信实际交付保留最小化、可脱敏的结果追踪，不记录回答正文和凭据。

完成门槛：安全边界进入自动化验收，核心领域文件不再依赖超大 switch 扩展。

### P4：个人工作流

- 微信内创建、重命名、编辑和删除项目快捷任务，不再要求修改 `config.json`。
- 一次成功任务可以直接“保存为快捷任务”，保存的是原始用户意图和项目归属，不复制 Codex 回答。
- 支持少量明确参数槽；启动时以卡片逐项询问，完成后直接进入任务队列，用户不需要记忆命令格式。
- 主菜单根据当前任务、队列、项目和最近一次结果动态推荐最多四个入口，固定保持低噪声，不新增命令墙。
- 最近一次结果支持“继续处理”“重试”“在新会话继续”和“保存为快捷任务”等自然短语；不额外发送低信息量操作卡。

完成门槛：用户只通过数字选择和自然语言即可创建并重复执行一个带参数工作流；重启后工作流与队列状态保持。

### P5：临时关注与自动化

- 支持“盯住这个服务，恢复或异常时通知我”这类临时关注，底层只使用已有 Git、systemd 和 HTTP 确定性检查。
- 临时关注必须声明项目、触发条件、检查周期和自动过期时间；默认 24 小时到期，避免永久噪声。
- 微信自动化中心支持创建、暂停、恢复和删除检查计划，不把自由文本直接保存为 Shell 命令。
- 多条变化合并为一张克制的移动摘要卡；相同指纹不重复通知，主动发送仍只使用通道真实支持的内容形式。

完成门槛：从微信创建一次临时健康关注，经历正常、异常、恢复和过期四种状态后，通知次数与状态文件完全一致。

### P6：视觉交付与项目记忆

- 每次任务生成确定性的“变更画册”：项目、会话、文件变更统计、测试结果和交付物分成 1–3 张高密度卡片；不读取或展示原始 diff、终端输出和凭据。
- 前端项目可以配置本机预览地址；任务前后由受限浏览器捕获截图并生成对比卡，网络范围仅限配置的本机地址。
- Codex 需要丰富排版时输出受限报告 schema，由 WeClaw 渲染为所选视觉模板的 PNG/PDF；不执行 Codex 返回的任意 HTML 或脚本。
- 用户显式发送“收藏这条”后，才把最近一次完整回答、交付引用和项目归属写入私有项目笔记；默认仍不永久保存回答正文。
- 项目笔记支持搜索、查看、取消收藏和“在新会话继续”，并明确显示来源时间与原项目。

完成门槛：同一前端任务能返回前后截图、确定性变更画册和可再次发送的交付物；收藏内容重启后可检索，未收藏回答不会进入长期状态。

## 5. 版本顺序

| 版本 | 范围 | 为什么先做 |
| --- | --- | --- |
| `v2.5` | P2 持久任务队列、全局执行协调器、排空与事务部署 | 先保证任务和升级不会丢，再允许更多后台能力 |
| `v2.6` | P3 状态存储统一、路由拆分、本地 API 安全 | 降低后续菜单和状态功能的扩展成本 |
| `v2.7` | P4 微信内快捷工作流与结果续接 | 直接解决命令记不住、重复输入费劲 |
| `v2.8` | P5 临时关注与微信内自动化管理 | 把 WeClaw 从被动问答升级为可靠助手 |
| `v2.9` | P6 变更画册、前后截图和显式项目记忆 | 提升手机上的交付质感与连续工作体验 |

当前只承诺开发 `v2.5`。后续版本在前一版本完成真机验收后再进入实现，避免菜单、状态和发送链同时扩张。

## 6. 功能取舍规则

每个新功能进入开发前必须同时回答：它属于哪条闭环、失败时用户看到什么、重启后状态在哪里、是否需要当前会话令牌、如何在微信真机验收。无法回答这五项的功能不进入主菜单。

优先级按“交付可靠性 → 核心工作流 → 使用频率 → 视觉精度 → 新奇程度”排列。视觉效果必须服务于内容密度和触屏阅读，不用装饰元素掩盖状态缺失。
