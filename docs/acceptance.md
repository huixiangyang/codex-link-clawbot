# 微信交互验收清单

## 自动化基线

```bash
go test ./...
go test -race ./codex ./messaging ./session ./config ./reporting ./visual
go vet ./...
systemctl --user is-active weclaw.service
curl --fail http://127.0.0.1:18011/health
```

工作树应保持干净，服务版本应与 `main` 最新部署版本一致，`~/.weclaw/renders` 不应残留 `card-*` 或 `document-*` 临时目录。

## 微信验收路径

### 1. 主控制台

1. 发送 `/`。
2. 预期收到主控制台图片和一条数字操作提示。
3. 图片应展示 WeClaw 版本、当前会话、任务状态、任务记录数量，以及会话、任务状态、任务记录、运行中心、工作目录、视觉风格和使用说明七个基础入口；配置了定时报告时，应在使用说明前额外显示“定时巡检”。
4. 回复 `0`，预期明确退出；随后发送普通问题应直接进入 Codex。
5. 进入“运行中心”，预期展示与主控制台一致的版本，以及启动时长、本地接口、Codex 协议、模型、工作目录和有效进程号；刷新后仍停留在运行中心。
6. 服务本地时间为 07:00–18:59 时，卡片应为明亮暖白主题；19:00–06:59 时应为深色主题。07:00 和 19:00 两个边界必须准确切换，画面不额外显示主题名称或渲染时间。
7. 主卡同时展示 6 个状态和 7 个入口时，短状态应为三列、短入口应为双列，图片不得出现数据/操作计数、仿点击箭头、内部页脚编号、大片空白、文字截断或页脚缺失。

### 2. 视觉风格

1. 发送“视觉风格”，预期看到刊物、构筑、黑标、可爱和简洁五项，并准确标记当前选择。
2. 依次切换五项；成功卡应立即使用刚选中的独立版式，而不是只改变强调色。
3. 刊物应呈现纸张、衬线和克制红；构筑应呈现平面石材、网格和建筑色；黑标应呈现高对比黑白和香槟金；可爱应呈现奶油纸、圆润轮廓和柔和色块；简洁应呈现高留白、细线和纯粹信息秩序。五者均不得出现霓虹渐变、无意义光晕、巨型水印、装饰计数或表情符号。
4. 每套风格都要分别验收控制卡和超过阈值的长回复；二者风格必须一致，文字、代码块、最后一个选项和页脚不得裁切。
5. 重启服务后，原绑定者应保持选择；另一个绑定者仍使用自己的选择或默认“构筑”。
6. 检查 `~/.weclaw/visual-styles.json`：严格 v1 JSON、文件权限 `0600`、父目录 `0700`，内容只保存绑定者与预定义模板 ID。

### 3. 会话管理闭环

1. 打开 `/`，选择“会话”。
2. 预期“会话中心”展示当前、可用数量、已归档数量。
3. 进入“当前会话”，预期可继续选择重命名、切换其他会话、归档当前会话。
4. 新建名为“明早验收”的临时会话，确认创建后普通消息会进入该会话。
5. 会话超过 6 条时，列表必须显示页码、总数和下一页；回复“下一页”“上一页”均应生效。
6. 从第 2 页点选一个会话，预期先显示详情和安全摘要而不切换；回复 `0` 应返回第 2 页。
7. 进入“搜索会话”，输入部分名称或字符顺序缩写；预期候选详情保留筛选词。明确发送“切换会话 名称”时，唯一匹配直接完成，多候选进入分页选择。
8. 当前和非当前会话的归档都必须二次确认；归档非当前会话不改变当前选择，归档后能在“恢复已归档会话”中找回。
9. 创建、切换、重命名、归档和恢复的成功卡片应提供下一步入口；详情只显示短编号，不显示完整 thread ID。成功卡片后直接发送普通问题，仍应进入 Codex 而不是被菜单吞掉。

### 4. 任务管理闭环

1. 发送一个预计执行 30 秒以上的只读检查任务。
2. 任务期间发送“状态”，预期收到运行时间、当前阶段、刷新和取消入口。
3. 选择刷新，预期仍停留在可操作状态卡片。
4. 选择取消，预期先出现影响说明和二次确认；回复 `0` 不取消，重新进入后回复 `1` 才取消。
5. 取消确认后，不应再收到该任务的迟到进度或最终回答。
6. 进入“任务记录”，预期最近任务显示安全摘要与完成/失败/取消状态；详情显示开始、结束、用时，回复 `0` 返回原分页。
7. 检查 `~/.weclaw/task-history.json` 权限为 `0600`，每个绑定者最多 20 条，内容不含回答、终端输出、附件名、私有路径或 thread ID。
8. 在测试任务运行中重启服务，重启后该记录应显示“重启中断”，而不是永久“运行中”。
9. 检查新产生的日志：不应出现原始微信用户/机器人 ID、用户问题、Codex 回答预览或媒体 URL/本机来源路径，只应出现 `id:xxxxxxxx` 短标签和字符数。

### 5. 长回复阅读模式

1. 要求 Codex 输出一篇包含标题、列表、引用和代码块且超过 900 字的项目分析。
2. 预期收到 1–10 张阅读卡片，页码和进度条连续，代码使用等宽样式。
3. 图片结束后应收到“文字版”提示。
4. 30 分钟内回复“文字版”，预期返回完整可复制原文，不启动新的 Codex turn。
5. 短回复继续保持普通文字，不产生多余图片。
6. 先打开任意菜单再回复“文字版”，取回后旧数字菜单必须失效；缓存过期或不存在时应明确提示，且不能启动 Codex turn。
7. 短阅读页应随内容收紧高度；32 个视觉容量单位的满载页必须完整展示最后一段和页脚，不得溢出或产生额外空白页。

### 6. 图片、文件和交付物

1. 在微信发送一张图片并要求分析，预期 Codex 能描述图片内容。
2. 发送一个普通文本或补丁文件，预期文件进入本次 turn 私有 inbox，不被桥接器执行。
3. 要求 Codex 生成交付文件，预期 outbox 文件先回传微信，最终回复随后到达。
4. turn 完成后 `~/.weclaw/turns` 不应残留对应任务目录。

### 7. 定时巡检管理

1. 配置至少 7 个测试计划后发送“定时巡检”，预期显示页码、计划总数、最近下次运行和前 6 个计划。
2. 回复“下一页”进入第 2 页，选择计划查看详情，预期展示状态、计划、时区、下次、上次、项目、服务和健康端点。
3. 在详情回复 `0`，预期返回第 2 页而不是第 1 页。
4. 设定时间前应显示“等待发送”；到点未成功发送应显示“等待重试”；成功后显示“今日已发送”。
5. 微信界面不应提供修改配置或强制执行入口。

## 不通过条件

- 群聊或非绑定账号可以驱动 Codex。
- 数字菜单吞掉普通对话，或过期数字仍执行旧操作。
- 会话列表暴露本地所有权索引之外的 Codex thread。
- 图片失败后没有完整文字兜底。
- “文字版”触发新的 Codex 请求。
- 归档或取消不经过确认。
- 巡检详情泄漏其他绑定者的发送状态，或从详情返回时丢失原分页。
- 任务记录跨绑定者泄漏，包含回答/私有路径，或重启后永久停留在“运行中”。
- 服务重启后当前会话丢失，或私有渲染、附件目录残留。
