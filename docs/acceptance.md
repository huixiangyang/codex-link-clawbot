# 微信端与部署验收清单

## 1. 项目、会话与主菜单

1. 空闲时发送 `/`，应只显示“项目、会话、任务中心、更多功能”四个主入口，并显示当前项目。
2. 执行中发送 `/`，入口应变为“当前任务、任务中心、当前会话、更多功能”，不得出现旧“暂存”入口。
3. 分别验证项目切换、快捷任务，以及会话新建、搜索、详情、切换、重命名、归档和恢复；分页返回保留页码与搜索词。
4. 切换项目后，会话列表不得出现其他项目会话；已入队任务仍使用创建时固定的项目和会话。
5. 任意旧工作目录切换或斜杠命令不得执行；配置中的 `codex.cwd` 必须导致启动失败。

## 2. 持久任务队列

1. 启动一个长任务，连续发送两条文字、一张图片和一个 PDF；四项都应在确认前落盘、只入队一次并按全局 FIFO 执行。
2. 忙碌期间切换项目、会话、回答方式和视觉风格；旧任务使用入队快照，新任务使用新选择。
3. “任务中心”每页显示 6 项，按状态提供移到最前、删除、暂停、继续、取消、重试或取回冻结文字；清空队列必须二次确认且只影响当前绑定者的等待项。
4. 暂停一个绑定者不应阻塞其他绑定者；远程锁定会取消当前任务并暂停该绑定者，解锁后不得自动恢复。
5. 重复投递相同 `message_id` 或 `seq` 不得创建第二项，也不得再次下载附件。
6. 分别在 `queued`、`running`、`delivering` 阶段终止进程：等待项继续排队，执行中和发送中任务转为人工处理中断，不得自动重复 Codex 或整批消息。
7. 详情不得展示完整问题、回答、附件名、原始账号 ID、`context_token`、终端输出或私有路径。

## 3. 投递事务

1. 明确拒绝发送时任务进入 `failed/delivery_failed`；响应丢失或部分媒体可能可见时进入 `interrupted/delivery_ambiguous`，两者恢复说明必须不同。
2. Codex 完成后必须先冻结正文、图片 URL、视觉风格、回答方式和交付物哈希，再进入 `delivering`。
3. 成功或取消后立即清理请求和结果；失败或中断负载最多保留 24 小时。
4. 语音模式必须先完整预上传阅读卡和 MP3，再依次发送；超长回答先发完整阅读卡，再发明确标注的语音节选卡与 MP3。
5. TTS、渲染或预上传在可见发送前失败时降级为完整阅读卡，再失败则发送全文；发送结果不确定时不得盲目补发。
6. 回答方式和视觉风格重启后保持；`preferences.json` 的未知字段、非法枚举、旧版本和尾随数据必须拒绝启动。

## 4. 图片、素材、交付与自动化

1. 图片和文件在排队时写入 `~/.weclaw/tasks/<task>/inbox`；Codex 执行时图片以 `localImage` 输入，文件只作为不可信附件引用。
2. 要求 Codex 生成文件，微信收到后“交付记录”应出现私有副本；任务临时目录清理后仍能再次发送。
3. 图片批注必须生成新 PNG，不覆盖原图；长回复按所选刊物、构筑、黑标、可爱或简洁风格生成阅读卡，“文字版”可取回全文。
4. 自动化详情必须直接读取受限 Git/systemd/HTTP 检查，不调用 Codex 或自由 Shell；相同指纹不得重复通知。

## 5. 游标、健康与排空

1. 入队写盘失败时不得推进微信同步游标；恢复磁盘后同一消息可以成功入队。
2. 一批消息中前项成功、后项失败时，私有消费回执应避免重做前项，同时保留整批旧游标。
3. `GET /health` 必须返回严格结构化 JSON，包括版本、运行状态、Codex、微信监控、任务数与排空状态；`starting/degraded/stopping` 返回 HTTP 503。
4. 排空期间仍可接收和持久化消息，但 Coordinator 不领取新任务。只有运行、发送、staging 和待提交同步批次都为零时 `drain_complete=true`。
5. `/admin/drain` 与 `/admin/resume` 只接受回环来源。

## 6. 事务部署与回滚

1. `update`、`upgrade`、daemon、PID 文件和 `scripts/cutover-local.sh` 必须不存在。
2. 发布部署使用 `weclaw deploy <version>`；本地构建使用 `weclaw deploy --binary /absolute/path --expect-version <version>`，候选必须自证精确版本和 Linux 架构。
3. 发布物必须通过 `checksums.txt` 的 SHA-256；任何下载、校验或版本错误都不得排空或替换服务。
4. 旧服务排空并停止后才创建一致状态快照和运行离线迁移。新服务先以排空模式启动，健康验收前不得领取旧队列。
5. 目标版本就绪后，systemd 单元不得残留 `--foreground` 或 `--draining`；队列显式恢复并发送纯文字部署通知。
6. 注入迁移失败、启动失败或版本不符，必须恢复旧二进制、systemd 单元、配置、同步游标和完整任务状态，并验证旧版本重新 `ready`。
7. 部署收据不得含正文、令牌或附件名；成功后立即删除包含私密任务负载的状态快照。

## 7. 自动化验证

```bash
go test ./...
go test -race ./taskqueue ./messaging ./ilink ./api ./cmd
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build ./...
```

最终真机验收至少覆盖：任务中心分页、文字/图片/PDF 连续排队、暂停与继续、取消、重启恢复、语音配对交付、部署通知和一次故障回滚。所有卡片不得泄露账号、路径、令牌、原始 diff 或终端输出。
