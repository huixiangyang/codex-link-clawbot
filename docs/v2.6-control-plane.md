# v2.6 可靠控制面与状态内核规划

## 当前实现进度

- 状态内核 A1 已完成：统一原子文件、稳定错误分类、容量限制、SHA-256 清单、故障注入、运行时/离线迁移互斥均已落地。
- 偏好、项目、远程锁、会话、自动化、素材库、微信游标、任务 JSON、配置和严格 v1 账号凭据已迁移，旧领域 writer 已删除。
- 类型化控制器 B 已完成：唯一意图注册、八个领域控制器、`ActionResult` 与统一 Presenter 已落地，旧大路由和五项跨消息副作用 map 已删除。详见 [类型化控制路由实现](v2.6-control-routing.md)。
- 持久菜单不做内存双写；C 批次直接切换到 revision 状态。详见 [统一状态内核实现](v2.6-state-kernel.md)。

## 1. 定位

v2.6 不扩张 Codex 执行能力，目标是把 v2.5 已经可靠的任务队列包进一个可审计、可扩展的控制面，为后续快捷工作流、临时关注和项目记忆提供稳定底座。

这一版解决四个具体问题：

1. 本地发送 API 目前只有网络边界，没有调用者身份与权限。
2. 微信意图、数字菜单和领域动作仍集中在大路由中，新增功能容易互相抢词或污染状态。
3. 十分钟菜单状态只在内存，服务重启后用户回复数字可能变成普通 Codex 输入。
4. 各领域重复实现严格 JSON、权限、原子替换和恢复，错误语义不完全一致。

## 2. 破坏性边界

- 删除无认证 `/api/send`；所有主动发送调用都必须使用显式凭据和最小权限。
- 管理 API 不再与发送 API 共用暴露策略；排空、恢复和部署提交只接受本机控制通道。
- 删除 `Handler` 中跨领域的 `sync.Map` 菜单状态；项目、会话、任务、偏好、素材和自动化各自拥有类型化控制器。
- 删除“无法识别就按顺序试多个 handler”的隐式路由。每个自然语言意图只归属一个领域，冲突在启动测试中直接失败。
- 删除内存菜单作为唯一事实来源；数字选择必须引用持久菜单 revision，过期或重启后明确拒绝，不进入 Codex。
- 不引入 SQLite 兼容层或双写。现有 JSON 状态一次性迁入统一状态内核后，旧写入器全部删除。

## 3. 控制面结构

```text
微信消息
  └─ Ingress Envelope
       ├─ source key / owner / context token / attachments
       └─ Intent Router
            ├─ Project Controller
            ├─ Session Controller
            ├─ Task Controller
            ├─ Preference Controller
            ├─ Library Controller
            └─ Automation Controller
                    │
                    ▼
              Typed Action Result
              ├─ card model
              ├─ short instruction
              ├─ queue request
              └─ delivery request
```

路由器只负责标准化文本、识别唯一意图和转交，不读取领域状态。控制器只返回类型化结果，不直接发送微信。最外层 Delivery Presenter 根据当前视觉风格统一渲染并投递。

每个动作声明：

- 稳定 action ID 与所属领域。
- 是否需要 `context_token`。
- 是否允许远程锁定、排空或任务执行期间调用。
- 是否修改状态、是否需要二次确认。
- 幂等来源键与安全审计摘要。

## 4. 持久菜单 revision

每个绑定者最多保存一项当前交互：

```json
{
  "version": 1,
  "owners": {
    "owner": {
      "revision": "random-id",
      "view": "task.detail",
      "expires_at": 1786000000,
      "options": [
        {"number": 1, "action": "task.retry", "subject": "task-id"}
      ]
    }
  }
}
```

正文、卡片图片、提示词、路径和 `context_token` 不进入菜单状态。用户回复数字时必须同时满足：当前绑定者、revision 未过期、目标仍属于该绑定者、动作仍适用于当前状态。服务重启后可以继续同一操作；过期数字只返回“操作已失效”，绝不交给 Codex。

所有改变状态的控制动作按微信来源键保存最小回执。长轮询重投时复用动作结果，不重复归档、删除、取消、锁定或触发快捷任务。

## 5. 统一状态内核

新增单一 `statefile` 包，所有领域状态复用：

- 严格版本、未知字段和尾随数据拒绝。
- 文件 `0600`、目录 `0700`，拒绝符号链接和非普通文件。
- 同目录临时文件、`fsync`、原子改名和父目录同步。
- 进程内读写锁与跨进程独占锁；离线迁移和运行时不能同时写。
- 固定大小上限、备份清单、校验哈希和孤儿临时文件清理。
- 统一错误分类：schema、权限、容量、损坏、冲突、暂不可用。

迁移顺序按风险从低到高：偏好与项目选择 → 菜单与远程锁 → 素材和自动化 → 会话索引。任务队列继续保留独立事务目录，但复用底层原子文件与锁实现。

## 6. API 权限模型

### 本机管理面

健康、排空、恢复和部署提交迁移到 Unix domain socket；CLI 固定连接该 socket，并校验 socket 所有者和 `0600` 权限。TCP 上不再暴露 `/admin/*`。

### 主动发送面

`/api/send` 默认关闭。启用时必须配置独立随机 token，并显式选择监听地址：

- 回环地址：Bearer token + `send:text` 或 `send:media` scope。
- 非回环地址：WeClaw 不直接提供明文 HTTP，必须放在用户配置的 TLS 反向代理后，并校验可信代理来源。
- token 只保存哈希；明文只在离线生成时显示一次。
- 请求需要 caller ID、幂等键、目标绑定者和严格大小限制；收据不保存正文。

部署通知不绕过权限模型，由本机管理面调用运行中服务的受限“通知所有绑定者”动作。

## 7. 自诊断

“运行中心”新增一个真正有用的“为什么没回复”入口，只读取确定性状态：

- Codex 是否就绪、最近一次退出原因。
- 微信监控是否健康、最后成功轮询距今多久、是否卡在待提交批次。
- 当前任务阶段、队列是否暂停或远程锁定。
- 任务存储剩余容量与最后一次持久化错误分类。
- 最近投递是成功、明确失败还是可能部分可见。

结果以一张高密度诊断卡呈现，提供最多三个下一步操作。不得展示账号 ID、正文、路径、URL 查询参数、命令输出或环境变量。

## 8. 开发批次

### A. 状态内核

- 已完成 `statefile`、锁、错误分类、故障注入、清单和现有状态迁移器。
- 已迁偏好、项目、远程锁、会话、自动化、素材、微信游标与任务 JSON；菜单在 C 批次直接建立 revision 状态，不保留旧内存双写。

### B. 类型化控制器

- 已完成 Intent Registry、Action Result 与 Presenter。
- 已按系统、项目、会话、任务、偏好、素材、自动化和安全拆分旧路由，删除旧大 switch 和跨领域 map。

### C. 持久交互

- 实现菜单 revision、幂等控制回执、重启继续和严格过期。
- 所有二次确认改为类型化 action，不保存显示正文。

### D. API 安全

- 管理面迁移 Unix socket；发送面增加关闭开关、token、scope、幂等和审计收据。
- 删除 TCP 管理端点与无认证发送路径。

### E. 诊断与真机验收

- 完成“为什么没回复”、状态故障注入、重启数字回复和 API 越权测试。
- 真实微信验证菜单重启续接、锁定、队列控制和诊断卡。

## 9. 验收矩阵

1. 在任务详情回复数字前重启服务，原操作仍可完成；过期 revision 明确拒绝且不启动 Codex。
2. 重投同一控制消息，快捷任务、删除、取消和远程锁各只执行一次。
3. 任意两个意图注册同一规范化短语时测试失败，不能依赖注册顺序。
4. 任一状态写入在 write、sync、rename 或目录 sync 注入失败后，旧文件仍完整可读。
5. 运行时持锁时离线迁移拒绝启动；迁移持锁时服务拒绝启动。
6. 未认证、错误 scope、重复幂等键冲突、超限正文和非可信代理请求全部拒绝。
7. TCP `/admin/*` 不存在；Unix socket 非所有者不可连接。
8. “为什么没回复”能分别识别队列暂停、远程锁、Codex 退出、微信监控异常、存储错误和投递歧义。
9. 所有卡片继续使用 Lucide 图标，不出现表情符号、内部路径、账号、令牌、原始输出或低信息量装饰。

## 10. v2.7 接口预留

v2.6 只预留三种类型化动作，不实现工作流产品：

- `workflow.save_from_task`
- `task.continue_in_thread`
- `task.continue_in_new_thread`

下一版可以直接把它们挂到任务成功详情和动态主菜单，而不修改任务状态机、消息游标或 API 权限模型。
