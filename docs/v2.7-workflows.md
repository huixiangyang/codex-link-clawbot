# v2.7 持久快捷工作流

## 当前进度

- F1 状态域已完成：新增严格 v1 `~/.weclaw/workflows.json`，按绑定者和项目隔离，支持创建、更新、删除、查找、排序、参数模板校验和确定性渲染。
- 旧 `projects[].quick_tasks` 已从运行时配置与项目管理器删除；离线迁移会单向导入，运行时没有兼容读取或双写。
- 项目中心和原“快捷任务”执行入口已改读工作流状态；无参数定义继续走现有持久入队与来源幂等链路。
- F2 微信内创建、编辑、重命名、删除和逐项参数收集尚待接入。
- F3 从成功任务保存、继续当前会话、在新会话继续和动态主菜单尚待接入。

## 1. 产品边界

快捷工作流保存的是用户希望重复执行的原始意图，不是 Codex 回答或终端输出。项目目录仍由配置白名单决定，工作流没有可由控制层直接执行的脚本字段，也不能携带 `cwd`、环境变量、模型、账号或发送目标；渲染结果只能作为普通 Codex 任务入队。

每个定义固定包含：

- 随机工作流 ID、项目 ID 和绑定者归属。
- 最多 32 字的名称。
- 最多 8,000 字的提示模板。
- 最多 8 个显式参数槽，每个槽包含稳定 ASCII key 和面向用户的短标签。
- 创建和更新时间。

每个绑定者在单个项目最多保存 24 项，全状态最多 128 项、2 MiB。状态文件使用统一状态内核，目录与文件权限分别为 `0700`、`0600`。

## 2. 参数模板

内部模板只接受 `{{slot_key}}`，每个占位符必须有且只有一个已声明参数槽，每个槽也必须真实出现在模板中。执行时要求值集合与声明完全一致，单值最多 1,000 字，渲染后最多 12,000 字；空值、多余值、残留括号和 NUL 一律拒绝。

微信创建界面不会要求用户记忆内部 key。F2 将使用可读标记收集模板并生成稳定 key，然后逐项显示参数标签。输入过程保存在工作流领域自己的短期运行状态，不能把提示模板或参数值写入通用菜单 revision。

## 3. 破坏性迁移

运行时 `Config` 已删除 `QuickTaskConfig`，项目管理器也不再持有快捷任务副本。旧配置直接启动会因未知字段失败。

隐藏的离线迁移按以下事务顺序处理：

1. 持有整个状态根的独占迁移锁。
2. 严格升级并读取账号凭据，确定全部绑定者。
3. 读取旧项目快捷任务并为每个绑定者生成确定性导入 ID。
4. 幂等写入 `workflows.json`；同 ID 内容不同或同项目名称冲突时失败，不覆盖现有定义。
5. 所有定义写入成功后，原子删除配置中的 `quick_tasks`。

没有绑定者时不允许把私密提示变成无归属共享数据。部署快照会自动包含新顶层状态文件，迁移或启动失败时与配置、二进制和其他状态一起回滚。

## 4. 后续批次

### F2 微信管理与运行参数

- 工作流中心、详情、创建、编辑、重命名和二次确认删除。
- 创建内容使用手机友好的字段提示，不引入命令墙。
- 有参数工作流逐项询问，重启后从当前参数继续；最终渲染后直接进入已有任务队列。
- 每个修改和最终运行都使用稳定微信来源回执；入队失败恢复最后参数状态。

### F3 结果续接与动态入口

- 成功任务详情增加“保存为快捷任务”，只读取仍可用的原始请求，不读取回答正文。
- 最近结果支持继续当前会话、重试和在新会话继续。
- 主菜单根据执行、等待、最近结果和当前项目工作流动态选择最多四项，不新增固定命令列表。

## 5. 验收门槛

- 旧配置迁移幂等，运行时严格拒绝旧字段。
- 创建、更新、删除在写入故障后不污染内存或旧文件。
- 绑定者、项目、参数和工作流 ID 不能越权访问。
- 一个带两个参数的工作流可以在微信逐项填写、重启续接并只入队一次。
- 成功任务能保存为工作流，但 `workflows.json` 中不存在回答、附件名、路径、令牌或命令输出。
