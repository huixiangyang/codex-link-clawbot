# 业务重整设计

用户已授权按需求基线连续完成设计与实现，不再重复请求阶段批准。

## 业务与存储

- 新增 `target.Store`，以持久化目标意图编号连接即时接收与真正创建线程。一个文件原子保存当前工作空间及各工作空间目标；活动请求只解析自身意图，不改写后来选择的目标。
- 请求索引升级为 v3，删除 queued、paused 与确认等待字段；忙碌拒绝只保存来源、会话及时间回执：保留处理阶段，增加执行完成时间、结果到期时间、结果容量。冻结结果即确定执行已完成；微信回执独立保存，投递失败不改写执行事实。
- 输入保留至终态后 24 小时，结果自冻结起保留 7 天；清理输入不删除结果。输入总量 500 MiB、结果总量 1 GiB，达到容量明确拒绝继续分配，不静默删除未到期结果。历史索引保留 30 天，上限 1000 条，达到上限拒绝新增。
- 删除生产链路中的重复交付物归档，结果目录作为回答与产物的唯一来源。旧存量产物通过离线迁移导入，备份保留。
- 单个绑定通过 CLI 明确选择；只有一个已保存绑定时可自动确定，多绑定无选择时启动报错并给出选择命令。
- 恢复操作使用操作编号去重；重跑创建关联原请求的新请求，重新投递仅发送已有冻结结果。重投要求本进程最近收到的真实微信上下文；不持久化可复用长期发送令牌。

## API 与交互

认证继续使用请求头令牌。新增请求列表筛选/分页、请求详情、结果文件下载、重跑与重新投递；取消必须携带精确请求编号。线程列表独立搜索/分页，当前目标独立读取；创建、选择、改名、归档通过受信任工作空间校验。设置基于当前能力整体保存。

微信另有独立单键数字菜单，调用同一组业务服务；布局、状态绑定、结果分页与重投处理见[数字菜单设计](../../docs/design/wechat-menu.md)。以下视觉规范针对网页管理台。

## 界面设计规范

用途：个人在手机或桌面检查远程工作、查看成果和处理异常。首屏应直接说明当前上下文与等待处理事项。

视觉方向：编辑式工业工作台。暖白纸面与深墨文字，醒目的请求编号、细分隔线和非对称双栏；避免用等权卡片堆叠运行指标。

配色：纸白 #F4F2EC、墨黑 #192321、灰绿 #69736D、苔绿 #286550、警示赭 #A74928。

字体：标题 Georgia / Noto Serif SC，正文 Avenir Next / PingFang SC，编号 Menlo；本机字体回退，页面不依赖外部字体服务。

布局：左侧窄导航和上下文栏，中央请求工作区，右侧结果阅读区；手机改为列表与详情两级视图。线程、设置通过独立面板进入。所有图标沿用 Lucide SVG，无表情符号。动效用于面板入场和状态变化，并尊重减少动态效果设置。

实现沿用 Go embed + 原生 JavaScript/CSS。项目现有 CSP 与无构建前端是确定约束，不为界面引入 Tailwind 运行时或前端框架。

## 验证

复用现有执行、媒体、状态安全测试；补充会话意图冻结、执行/投递分离、留存与恢复去重、精确取消、认证下载与能力校验的必要回归。完成 Go race/vet/build、JS 语法检查与本地隔离页面流程验证；不启动真实微信服务或操作桌面应用。

离线迁移先生成私有备份，再升级业务索引和导入历史产物。运行时只接受新格式。不会在本次开发中迁移或清理用户真实数据。

## HTTP 契约

所有 API 要求 `X-Codex-Link-Token`，使用当前唯一绑定的所有者范围，并返回 `Cache-Control: no-store`。恢复操作编号为 UUID。

| 方法与路径 | 用途 |
| --- | --- |
| GET `/api/snapshot` | 当前目标、连接、会话状态、可用模式与偏好 |
| GET `/api/requests?view=all&page=1&q=关键词` | 请求搜索与分页；view 支持 active、attention、history、all |
| GET `/api/requests/{id}` | 输入摘要、回答、文件、独立投递记录 |
| GET `/api/requests/{id}/artifacts/{index}` | 归属与完整性校验后的附件下载 |
| POST `/api/requests/{id}/actions` | action: cancel、retry、redeliver；恢复带 operation_id |
| GET/POST `/api/conversations` | 分页搜索／新建会话 |
| GET `/api/conversations/{id}` | 当前活动请求/原生轮次与实时状态 |
| POST `/api/conversations/{id}/actions` | rename、archive、interrupt；打断携带 task_id 或 turn_id |
| PUT `/api/target` | 原子选择 workspace_id 与可选 thread_id |
| PUT `/api/preferences` | 整体提交 response_mode 与 style |
| POST `/api/runtime` | drain、resume |
| POST `/api/lock` | locked 布尔值，解锁需 code |

旧 API 不保留别名。迁移步骤见[离线迁移](../../docs/operations/migration.md)，验证结果见[验证记录](../../docs/operations/business-validation.md)。
